# Data directory

This repository ships a small amount of reference data to make it easier to reproduce
integration tests and demonstrations. The directory is version-controlled because it
contains hand-curated CSV inputs that the test suite expects.

## Layout

- `input/` – Immutable source fixtures checked into git. These CSV files mirror the
  structures published by ChEMBL and provide stable inputs for automated tests and
  examples. They should only change when the upstream schema or sample content changes.
- `cache/` – Derived artefacts generated by the ETL jobs (for example, molecule cache
  databases). These files are safe to delete locally; the pipelines will recreate them on
  demand. They are committed so that developers can run examples without a full refresh,
  but you should avoid editing them manually.
- `run.but` – A developer convenience script that documents typical command invocations
  used during manual runs. It is not executed automatically and may be adapted locally.

## Guidelines

- Only commit new files in `cache/` if they are required for deterministic tests or
  documentation. Ephemeral runtime output should be redirected to a separate, ignored
  location (for example `var/`).
- When adding new inputs, document their provenance and expected schema in commit
  messages or accompanying documentation.
- If you regenerate cached artefacts, include a brief note in the commit explaining why
  the refresh is necessary.
