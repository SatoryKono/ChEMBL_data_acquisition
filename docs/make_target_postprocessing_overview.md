# make_target_postprocessing.py Overview

## Purpose

`make_target_postprocessing.py` orchestrates the command-line interface (CLI) that finalises the **targets** dimension within the ChEMBL data acquisition pipeline. It takes raw target exports generated by earlier ingestion steps and applies the declarative post-processing pipeline so that the resulting dataset conforms to the expected schema, contains harmonised identifiers, and is accompanied by reproducible quality metrics.

## Invocation Flow

1. **Bootstrap and Imports**  
   The script adjusts the Python path for standalone execution and imports CLI helpers, shared logging utilities, pipeline configuration helpers, and the target-specific pipeline runner and schema validators.【F:scripts/make_target_postprocessing.py†L1-L82】

2. **Argument Parsing**  
   `build_parser()` defines required `--input` and `--output` CSV arguments plus optional overrides for the pipeline configuration, log level, and run identifier.【F:scripts/make_target_postprocessing.py†L84-L123】

3. **Pipeline Version Resolution**  
   `resolve_pipeline_version()` determines the version string used for metrics and validation. It honours explicit CLI overrides, configuration defaults (`params.defaults.pipeline_version`), and falls back to the package-level version helper.【F:scripts/make_target_postprocessing.py†L125-L160】

4. **Runtime Execution (`run`)**  
   * Loads the declarative pipeline definition and derived CSV runtime settings when they are not injected externally.【F:scripts/make_target_postprocessing.py†L162-L181】  
   * Injects the resolved configuration into `library.postprocessing.targets.steps` so step orchestration uses the current runtime definition.【F:scripts/make_target_postprocessing.py†L183-L186】  
   * Builds a `PostprocessingPipelineConfig` bundle that wires in the targets pipeline runner, schema validator, runtime CSV settings, logger, and pipeline version.【F:scripts/make_target_postprocessing.py†L187-L205】  
   * Calls the generic `run_postprocessing_pipeline()` helper which performs: loading the input CSV with deterministic options, executing the configured step sequence, schema validation, and exporting the final CSV together with a JSON metrics report.【F:scripts/make_target_postprocessing.py†L207-L230】【F:library/postprocess/common.py†L229-L318】  
   * Handles CSV parsing errors, schema violations, missing files, and unexpected exceptions with structured log events and non-zero exit codes.【F:scripts/make_target_postprocessing.py†L207-L233】  
   * Logs pipeline metrics summary and generates an auxiliary metrics report (or reuses the in-memory metrics) that captures output dimensions and contextual metadata.【F:scripts/make_target_postprocessing.py†L235-L264】

5. **CLI Entry Point (`main`)**  
   The entry point parses arguments, resolves the declarative pipeline config, negotiates logging (including deterministic run identifiers and log destinations), and delegates to `run()` inside a context manager that configures structured CLI logging.【F:scripts/make_target_postprocessing.py†L266-L324】

## Target Pipeline Steps

The declarative configuration `config/pipeline/targets.yaml` activates three ordered transformations.【F:config/pipeline/targets.yaml†L1-L28】

1. **`normalize_target_fields`** – Standardises identifiers, trims whitespace, optionally harmonises taxonomy fields, coerces numeric taxonomy identifiers, and backfills missing `target_chembl_id` values using alternate columns. It can also normalise taxonomy metadata when enabled.【F:library/postprocessing/targets/steps.py†L1-L105】

2. **`enrich_target_synonyms`** – Consolidates synonym sources (core field plus configured dictionary-based columns), deduplicates tokens case-insensitively, and renders a stable, separator-controlled string or `NA` when nothing is available.【F:library/postprocessing/targets/steps.py†L107-L168】

3. **`finalize_target_records`** – Ensures required columns exist, coerces string types, fills missing `target_type` values via a bundled dictionary lookup, validates the frame against `TARGET_SCHEMA`, and optionally sorts by configured columns (default `target_chembl_id`).【F:library/postprocessing/targets/steps.py†L170-L276】【F:library/postprocessing/targets/schema.py†L1-L32】

The pipeline runner `run_target_pipeline()` executes these steps through the shared `run_steps()` engine, capturing `PipelineRunMetrics` that summarise row counts, column counts, and pipeline version lineage.【F:library/postprocessing/targets/steps.py†L278-L319】

## Output Artefacts

During execution the script produces:

- A postprocessed CSV at the requested `--output` path, respecting deterministic column ordering and sorting enforced by the schema.【F:library/postprocess/common.py†L342-L368】
- A JSON metrics report (`targets.postprocess.report.json`) collocated with the output CSV. It contains row/column counts, pipeline version, and optional extra context such as input/output locations.【F:library/postprocess/common.py†L320-L368】
- Structured log statements (optionally persisted under `logs/`) that describe loading, pipeline execution, validation, export, and report generation phases.【F:scripts/make_target_postprocessing.py†L203-L264】

## Error Handling and Validation

- Missing input files raise `FileNotFoundError` and emit a `targets_postprocess_input_missing` error log.【F:scripts/make_target_postprocessing.py†L222-L230】
- CSV parsing issues are captured as `io.CsvReadError`, logged with the underlying parser error, and halt execution.【F:scripts/make_target_postprocessing.py†L209-L216】
- Schema violations or step-level failures propagate as `SchemaValidationError`/`StepError` with stack traces for diagnostics.【F:scripts/make_target_postprocessing.py†L216-L220】
- Unexpected exceptions are guarded with a catch-all handler to ensure the CLI exits with status code `1`.【F:scripts/make_target_postprocessing.py†L220-L223】

## Interaction with Other Modules

- `library.postprocessing.targets.__init__` exposes the schema, pipeline steps, and helper functions leveraged by the CLI while enabling runtime overrides for search directories used by underlying enrichment utilities.【F:library/postprocessing/targets/__init__.py†L1-L34】
- Shared CLI infrastructure (`library.cli`, `library.cli_utils`, `library.cli.logging`) supplies consistent logging configuration, argument parsing helpers, and run identifier management across post-processing commands.【F:scripts/make_target_postprocessing.py†L27-L80】
- `library.postprocess.common` provides the generic orchestration helpers (loading CSVs, executing pipelines, validation, exporting, and metrics reporting) reused by all domain post-processors, ensuring behavioural parity.【F:library/postprocess/common.py†L1-L433】

Together these components ensure that `make_target_postprocessing.py` deterministically converts raw target exports into validated, enriched datasets ready for downstream integration.
