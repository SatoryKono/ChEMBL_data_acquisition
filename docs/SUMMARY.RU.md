# Краткое резюме проекта
- ChEMBL Data Acquisition — набор CLI-скриптов и библиотек на Python 3.12 для скачивания, нормализации и экспорта биоданных из API ChEMBL, PubChem, UniProt, PubMed и смежных источников с детерминированным выводом в CSV/Parquet.


- В проект включены унифицированные флаги запуска, потоковая обработка CSV, схемы валидации и справочники, а также инфраструктура логирования и метаданных выполнения.


- Документация охватывает установку, pre-commit, smoke-команды и тесты, обеспечивая воспроизводимый пайплайн для новых участников команды данных.


- Конфигурация управляется YAML-файлом с поддержкой переопределений через переменные окружения и CLI; структура задокументирована в [CONFIG_RU.md](CONFIG_RU.md) (английская версия — [CONFIG_EN.md](CONFIG_EN.md)).


- Выходные таблицы сопровождаются sidecar-файлами с хешами, конфигурацией и статистикой, что упрощает аудит и мониторинг качества данных.



- Проект ориентирован на строгую типизацию, использование pandera для схем и полный пакет проверок качества (black, ruff, mypy, pytest, deterministic CSV).



- Текущая документация не содержит roadmap или известных проблем — README фокусируется на запуске, тестах и генерации данных без упоминания будущих задач.



## Архитектура и модули
- **scripts/** — CLI-обвязки для отдельных пайплайнов (activities, assays, targets и т.д.) с обработкой ошибок, нормализацией, pandera-валидацией и генерацией sidecar-файлов.


- **library/** — основной код:
  - `io.py` — чтение идентификаторов/CSV и запись детерминированных CSV с автоматическим созданием метаданных и директорий.


  - `chembl_client.py` — HTTP-клиент с кэшированием, лимитами RPS и экспоненциальным бэкоффом для API ChEMBL.


  - `document_pipeline.py`, `target_postprocessing.py`, `input_initialisation_library.py` — модули агрегации и пост-обработки, повторяющие производственный Power Query-процесс с вычислением показателей, маппингом справочников и статистикой фильтрации.



  - `cli/` — единая сборка парсеров, загрузка конфигурации, настройка логгера и общих аргументов (input/output/encoding/chunk-size и т.д.).


  - `logging_setup.py`, `log.py` — структурированное JSON-логирование с редактированием секретов и глобальным логгером, привязанным к статусу и RPS.



  - `metadata.py`, `sidecar.py`, `pipeline_metadata.py` — формирование sidecar YAML, подсчёт SHA-256, добавление версии пайплайна и штампа времени в данные.




- **schemas/** — pandera-схемы и нормализаторы (activities, targets, documents, testitems) с проверками значений и типов.


- **docs/** — справочные инструкции по запуску, конфигурации и выходным артефактам.



- **tests/** — широкое покрытие CLI, конфига, валидации, пост-обработки и детерминизма; пример — smoke-тест активности и проверки работы конфига/пайплайна таргетов.




## Поток данных (схема)
```
[CSV идентификаторов]
        │ read_ids()
        ▼
[Итератор ID] --limit--> [Порции ID]
        │ ChemblClient/request_json() + rate limiting
        ▼
[Сырые данные API] --normalize_*/postprocess--> [DataFrame]
        │ Pandera validation + SidecarErrors
        ▼
[Очистка и агрегация]
        │ add_pipeline_metadata()
        ▼
write_csv() ──► <table>.csv + <table>.csv.meta.yaml + (опц.) failure_cases.csv
```
- Чтение идентификаторов с обработкой пустых значений и проверкой колонок происходит через `read_ids`.


- Извлечение API выполняется в `ChemblClient` с кэшем, ограничением по RPS и экспоненциальным бэкоффом.


- Нормализация, валидация и сбор sidecar-ошибок реализованы в CLI-скриптах с использованием pandera и `SidecarErrors`.



- Запись CSV и метаданных производится через `write_csv`, `write_meta_yaml` и добавление столбцов версии/времени.




## Конфигурация
- Верхний уровень `config.yaml` разделён на блоки `sources`, `local`, `activity_bounds` и `system`.


- `sources` описывает все удалённые зависимости: `sources.chembl.api` задаёт базовые URL, ретраи, троттлинг и заголовки; `sources.chembl.cache` и `sources.chembl.molecule_catalog` управляют локальными кешами; `sources.chembl.pipelines.*` фиксирует колонки идентификаторов, размеры батчей и лимиты для пайплайнов; соседние секции (`sources.openalex`, `sources.crossref`, `sources.uniprot.api`/`mapping`, `sources.iuphar`, `sources.pubchem`, `sources.pubmed`, `sources.semantic_scholar`) аналогично настраивают сети и rate limit.


- `local` агрегирует файловую структуру: `local.resources` описывает каталоги словарей и ссылочных CSV, `local.io` унифицирует каталоги вывода/кеша и CSV-параметры, а `local.init` перечисляет Excel-источники и директории для пайплайна инициализации.


- `activity_bounds` управляет вычислением диапазонов из relation-строк, включая точность округления, ограничение отрицательных значений и логирование неизвестных токенов.


- `system` централизует глобальное поведение через `system.log`, `system.rate`, `system.retry` и весовые таблицы `system.doc_type`.


- Pydantic-модели обеспечивают типизацию, валидацию адресов и обязательного `user_agent` с email; порядок приоритетов: YAML < env < CLI.


- Документация описывает структуру и переопределения через переменные `CHEMBL_DA__SECTION__KEY`, короткие алиасы и ключи `--section.key=value`.


- Тесты проверяют, что пустой YAML подставляет дефолтные RPS, что переменные окружения и алиасы корректно перекрывают значения, а отсутствующий файл вызывает `ConfigError`.



## Словари/справочники
- Конфигурация указывает базовый каталог `dictionary`, пути к IUPHAR и UniProt справочникам, а также `targets_type.csv` и связанные csv-файлы для классификации таргетов.


- Модуль `input_initialisation_library` использует файлы `dictionary/_Curation/citation_fraction.csv` и `dictionary/_Target/targets_type.csv` для расчёта показателей цитирования, типов таргетов и других атрибутов; при отсутствии файлов генерируется понятная ошибка с ожидаемыми путями.


- В процессе обогащения таблиц используется чтение локальных UniProt JSON и CSV классификаций, что позволяет согласовать внешние справочники с выгрузкой ChEMBL.




## Зависимости и установка
- Минимальные версии Python 3.12, pandas 2.1, requests 2.31, PyYAML 6.0; полный список зависимостей и dev-инструментов (black, ruff, mypy, pytest, responses, hypothesis и т.д.) задекларирован в pyproject.toml.



- Установка выполняется через `pip install .[dev]` или `pip install -e .[dev]`, рекомендуется виртуальное окружение и обновление pip/setuptools/wheel.



- После установки активируется `pre-commit install` для автозапуска форматирования, линтинга и статических проверок перед коммитами.



## Как запустить (шаги)
1. Клонировать репозиторий и создать виртуальное окружение Python 3.12, активировать его.


2. Установить зависимости проекта и dev-инструменты через `pip install .[dev]`.


3. Запустить `pre-commit install` и (при необходимости) `pre-commit run --all-files` для первичной проверки качества.


4. Подготовить входной CSV с колонкой идентификаторов (по умолчанию `input.csv`/`activity_chembl_id`).
   - Название колонки берётся из `sources.chembl.pipelines.activity.column` в конфигурации (дефолт `activity_chembl_id`) и может быть переопределено флагом `--column` или через `config.yaml`.


5. Выполнить нужный CLI-скрипт, например `python -m scripts.get_activity_data --input tests/data/activity_ids_small.csv --output out/activities.csv --limit 10 --log-level INFO`, чтобы выгрузить данные и записать CSV вместе с метаданными.


6. Альтернативные пайплайны: `get_assay_data`, `get_target_data`, `get_document_data`, `get_testitem_data`, `get_input_initialisation`, `table_quality_main`.


7. Проверить созданные CSV и `.meta.yaml` в `data/output` (или указанном каталоге).



## Тесты и проверка результатов
- Общие проверки качества: `pre-commit run --all-files`, `pytest`, `scripts/check_determinism.py --log-level DEBUG`. Эти команды обеспечивают форматирование, линтинг, типизацию, юнит-тесты и детерминизм вывода.


- Smoke-тесты CLI подтверждают успешную генерацию CSV при подключении заглушек API и хешированию файлов.


- Тесты конфига проверяют сценарии с алиасами, env-переменными и отсутствующими файлами, что помогает диагностировать проблемы настройки до запуска пайплайна.


- Пайплайн-ориентированные тесты гарантируют корректную передачу batch_size, обработку необязательных стадий и возвращение DataFrame с ожидаемыми колонками.


- Детерминированная запись CSV проверяется как отдельным скриптом, так и юнит-тестами на совпадение SHA-256 хешей при повторной сериализации данных.




## Выходные артефакты (таблицы/файлы, поля, примеры)
- Основные результаты — CSV-файлы в каталоге `io.output_dir` (`data/output` по умолчанию) с опциональными поддиректориями, отражающими источник или стадию обработки.


- Каждый CSV сопровождается `<name>.csv.meta.yaml`, содержащим git SHA, команду запуска, конфиг, статистику строк/колонок и SHA-256 основного файла.


- При валидационных ошибках создаются отдельные `*_failure_cases.csv` через `SidecarErrors`, что упрощает анализ проблемных строк.



- `table_quality_main.py` и `get_input_initialisation.py` дополнительно формируют отчёты качества (`<table>_quality_report_table.csv`, `<table>_data_correlation_report_table.csv`).


- В данные автоматически добавляются столбцы `pipeline_version` и `timestamp_utc` для трассируемости выпусков.




## Логи и диагностика
- Логирование основано на собственном JSON-логгере с редактированием чувствительных данных и глобальным контекстом; уровень и run_id настраиваются через CLI/конфиг.




- CLI-скрипты логируют ключевые события: чтение входа, лимит, запросы, ошибки API, результаты валидации и запись файлов, что облегчает расследование инцидентов.


- Метаданные выводятся в sidecar YAML вместе с хешами и конфигурацией, предоставляя дополнительный уровень диагностики для истории запусков.




## Ограничения и предположения
- Требуется Python 3.12, доступ к интернету (порт 443) и корректный `user_agent` с email для API, иначе валидация Pydantic завершится ошибкой.



- Настройки RPS, таймаутов и backoff заданы по умолчанию, но могут потребовать корректировки при ограничениях API; лимиты выполняются через `ChemblClient` и `rate_limiter`.



- Справочники ожидаются в структуре `dictionary/…`; отсутствие ключевых CSV вызывает исключения, что требует предварительной синхронизации локальных словарей.



- README не содержит roadmap или известных проблем — дополнительные ограничения и планы развития необходимо уточнять отдельно.



## Частые ошибки и как их решать
- **Отсутствие входной колонки/файла** — `read_ids` и CLI логируют `read_fail`; проверьте имя колонки (`--column`) и путь к CSV.


- **Неверные лимиты/параметры** — при отрицательном `activity.limit` логируется `invalid_limit`; исправьте значение в `config.yaml` или CLI.


- **Сбой API** — `ChemblClient` логирует `request_fail` и использует повторы; при устойчивом фейле проверьте сеть, таймауты и user agent.


- **Отсутствие словарей** — `targets_type.csv` или `citation_fraction.csv` отсутствуют → FileNotFoundError с подсказкой о путях; синхронизируйте `dictionary` или передайте `--dictionary`.


- **Нет конфига** — попытка загрузить несуществующий YAML вызывает `ConfigError`; создайте файл или используйте дефолтный путь.


- **Проблемы с валидностью данных** — при несоответствии схеме создаются `*_failure_cases.csv`; изучите файл, обновите словари или очистку, повторите запуск.



## Глоссарий терминов (ChEMBL/ETL)
- **ActivitiesSchema** — pandera-схема для таблиц активности (колонки, проверки диапазонов).


- **Sidecar** — дополнительный CSV с ошибками валидации или YAML с метаданными запуска, формируется автоматически при записи результатов.



- **Pipeline metadata** — столбцы `pipeline_version` и `timestamp_utc`, добавляемые ко всем выводам для отслеживания версии пайплайна и времени запуска.


- **Deterministic CSV** — стратегия сортировки строк/колонок и проверки SHA-256 для обеспечения идентичного вывода при повторных запусках.



- **Input initialisation** — процесс объединения исходных Excel/CSV, фильтрации и распределения по сущностям (activity, assay, target, document, testitem) с расчётом статистик.



## Требования к качеству
- Обязателен запуск форматирования, линтинга, статической типизации и pytest через pre-commit либо напрямую перед релизом.


- Данные должны проходить pandera-валидацию; ошибки фиксируются в sidecar и считаются блокирующими, пока не устранены.


- Должна сохраняться детерминированность CSV (проверяется unit-тестами и скриптом).



- Каждый выход сопровождается метаданными с хешами и конфигурацией; отсутствие sidecar-файлов считается нарушением требований воспроизводимости.




## Проверочный чек-лист запуска
1. Python 3.12 установлен, доступ к сети (443) проверен.


2. Создано и активировано виртуальное окружение; pip/setuptools/wheel обновлены.


3. Выполнено `pip install .[dev]` без ошибок зависимостей.


4. Запущен `pre-commit install`; при необходимости `pre-commit run --all-files`.


5. Подготовлен входной CSV с ожидаемой колонкой идентификаторов (или передан `--column`).


6. Проверено наличие словарей `dictionary/…` или передан путь `--dictionary`.



7. Выполнена целевая команда (`python -m scripts.get_activity_data ...` и т.п.) с нужными флагами и лог-уровнем.



8. Убедились в создании CSV и `.meta.yaml` в `data/output` (или указанном каталоге).


9. Проверены логи/JSON на отсутствие ошибок и наличие run_id.


10. При необходимости запущены `pytest` и `scripts/check_determinism.py --log-level DEBUG`.


11. В случае ошибок валидации просмотрены `*_failure_cases.csv` для исправления данных.


12. Конфигурационные overrides (CLI/env) задокументированы вместе с артефактами запуска.




## One-liner setup & run
```
python -m venv .venv && source .venv/bin/activate && pip install .[dev] && python -m scripts.get_activity_data --input tests/data/activity_ids_small.csv --output data/output/activities.csv --limit 10 --log-level INFO
```
