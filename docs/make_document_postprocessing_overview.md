# Обзор `make_document_postprocessing.py`

В этом документе описывается, как команда `scripts/make_document_postprocessing.py`
организует постобработку таблицы `documents`, которая завершает предыдущие этапы
пайплайна ChEMBL Data Acquisition.

## Точка входа командной строки

Модуль инициализирует общие CLI-хелперы и предоставляет функцию `main()` в качестве
точки входа, используемой релизными скриптами. Команда принимает четыре основных
аргумента:

* `--input` – путь к сырому CSV-файлу с документами, который ещё предстоит
  гармонизировать.
* `--output` – путь (файл или директория), куда следует записать постобработанную таблицу.
* `--config` – необязательный YAML с описанием пайплайна, позволяющий переопределить
  стандартный набор шагов.
* `--log-level` и `--run-id` – необязательные параметры для настройки логирования (второй
  также может быть передан через переменную окружения `CHEMBL_DA_RUN_ID`).

Парсер реализован в функции :func:`build_parser` и использует общий хелпер
`path_argument` для нормализации путей к файлам.【F:scripts/make_document_postprocessing.py†L105-L144】

## Загрузка конфигурации пайплайна

Скрипт загружает (или получает во время тестов) структуру :class:`PipelineConfig`
с декларативным описанием пайплайна, после чего рассчитывает эффективные параметры
работы с CSV и версию пайплайна, которая будет записана в результаты. Определение
версии происходит по каскаду:

1. Явное значение, переданное в :func:`resolve_pipeline_version`.
2. Поле `pipeline_version` в корне YAML-файла.
3. Значение `params.defaults.pipeline_version` из того же YAML.
4. Фолбэк к строке версии из `get_pipeline_version()`.

Такая схема позволяет пользовательским настройкам и переменным окружения иметь
приоритет, сохраняя при этом детерминированный фолбэк при отсутствии явных значений.【F:scripts/make_document_postprocessing.py†L147-L187】
Стандартная конфигурация хранится в `config/pipeline/documents.yaml` и включает три
шага с их параметрами, а также общие настройки ввода-вывода и логирования.【F:config/pipeline/documents.yaml†L1-L31】

После загрузки конфигурации скрипт обновляет рабочие объекты в модуле
`library.postprocessing.documents.steps`, чтобы оркестратор использовал кастомизированную
последовательность шагов.【F:scripts/make_document_postprocessing.py†L269-L278】

## Работа с входом и именование вывода

Перед запуском пайплайна команда определяет итоговую точку назначения для вывода.
Если `--output` указывает на директорию или не содержит расширения, скрипт формирует
имя файла по конвенции Stage и добавляет префикс `documents`
(`extended.output.document_…`). Это гарантирует детерминированные имена артефактов
в разных окружениях.【F:scripts/make_document_postprocessing.py†L188-L205】

Сырой CSV загружается с помощью общего хелпера :func:`load_input_frame`, который
применяет заданную кодировку/разделитель и логирует операцию. Любые ошибки чтения
преобразуются в структурированные события и прерывают выполнение.【F:scripts/make_document_postprocessing.py†L208-L314】【F:library/postprocess/common.py†L87-L141】

## Шаги трансформации

Непосредственные преобразования делегируются доменно-специфическому пайплайну из
`documents.yaml`. В стандартной конфигурации выполняются три функции из
`library.postprocessing.documents.steps`:

1. **`normalize_document_fields`** – удаляет лишние пробелы, при необходимости
   нормализует Unicode в ключевых текстовых колонках (`title`, `journal`, `doc_type`) и
   приводит имена столбцов к нижнему регистру. Пустые строки заменяются корректными
   маркерами `NA`.【F:library/postprocessing/documents/steps.py†L20-L48】
2. **`enrich_document_publication_year`** – формирует новую nullable-колонку
   `publication_year`, отдавая приоритет исходному значению из ChEMBL, затем
   последовательно используя дополнительные источники (`crossref.*`, `openalex.*`,
   `scholar.*`, `pubmed.*`). Значения приводятся к целым числам в допустимом диапазоне,
   а опциональные фолбэки (например, год по умолчанию `1900`) учитываются.【F:library/postprocessing/documents/steps.py†L67-L136】【F:config/pipeline/documents.yaml†L10-L15】
3. **`finalize_document_records`** – дополняет отсутствующие идентификаторы из
   резервных колонок, фиксирует строковые типы для обязательных полей, приводит
   `publication_year` к nullable-целому и при необходимости удаляет дубликаты
   `document_chembl_id`, после чего валидирует фрейм по канонической схеме.【F:library/postprocessing/documents/steps.py†L139-L223】【F:config/pipeline/documents.yaml†L16-L21】

Утилита `run_postprocess_steps` оборачивает эти функции, снимает метрики по шагам и
логирует изменения схемы для трассируемости.【F:library/postprocess/common.py†L116-L141】

## Валидация схемы и порядок данных

После завершения преобразований скрипт валидирует DataFrame с помощью
`DOCUMENT_SCHEMA`. Схема задаёт обязательные колонки (`document_chembl_id`, `title`,
`doc_type`), опциональные поля, ожидаемые типы данных и канонический порядок колонок с
базовой сортировкой. Валидация выполняется дважды: внутри шага
`finalize_document_records` (если её не отключили явно) и после завершения пайплайна
через :func:`validate_postprocess_frame`, что гарантирует корректность экспортируемого
CSV.【F:library/postprocessing/documents/schema.py†L7-L45】【F:scripts/make_document_postprocessing.py†L231-L245】【F:library/postprocess/common.py†L294-L309】

## Экспорт и метрики

Финальный фрейм записывается с детерминированным порядком и сортировкой ключей
через :func:`export_postprocess_frame`, что обеспечивает стабильные диффы между
запусками. Рядом с CSV сохраняется отчёт с метриками (JSON), сформированный
функцией :func:`generate_metrics_report`. Если пайплайн уже посчитал метрики (типичный
случай), они переиспользуются; иначе хелпер пересчитает их на основе сохранённого CSV.
Оба действия дополняются контекстом о путях входных и выходных файлов для аудита.【F:scripts/make_document_postprocessing.py†L248-L360】【F:library/postprocess/common.py†L183-L325】【F:library/postprocess/common.py†L328-L379】

## Логирование, ошибки и коды возврата

Все ключевые события (старт, загрузка, валидация, экспорт, сводки) логируются с
структурированными полями. Критические проблемы — отсутствие входа, ошибки чтения CSV,
нарушения схемы или непредвиденные исключения — фиксируются в логах с контекстом и
приводят к завершению работы со статусом 1. Успешное выполнение сообщает размеры
обработанного датасета и завершает работу с кодом 0.【F:scripts/make_document_postprocessing.py†L283-L361】

## Сводка по входу и выходу

* **Вход** – CSV, сформированный предыдущим этапом пайплайна; должен содержать сырые
  записи документов ChEMBL и вспомогательные колонки обогащения (поля CrossRef/OpenAlex/
  PubMed), необходимые для расчёта года публикации.
* **Выход** – нормализованный CSV, отсортированный по `document_chembl_id`, с
  гармонизированными текстовыми полями, валидированной схемой и согласованными
  идентификаторами, а также JSON-отчёт с метриками, где фиксируются статистики и
  происхождение данных.【F:library/postprocess/common.py†L183-L325】

В совокупности эти шаги обеспечивают «финальную милю» очистки метаданных документов,
гарантируя, что потребители получают стабильный, прошедший валидацию экспорт с наиболее
надёжными сведениями о публикациях, доступными на момент загрузки.
