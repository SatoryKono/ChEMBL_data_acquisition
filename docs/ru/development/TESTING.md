# Политика тестирования

Pytest-сьют должен оставаться детерминированным и изолированным.

## Структура каталогов

```
tests/
  unit/
  integration/
  e2e/
  resources/
  conftest.py
```

- **unit** — модульные тесты функций и классов.
- **integration** — взаимодействие модулей, проверка CSV и словарей.
- **e2e** — запуск CLI на тестовых данных с проверкой логов и идемпотентности.

## Требования к детерминизму

- Фиксируйте `PYTHONHASHSEED`, seed Python и NumPy (`tests/conftest.py::deterministic_env`).
- Не зависите от текущего времени и локали.
- Сеть по умолчанию отключена — используйте моки или сохранённые ответы.
- Для временных файлов применяйте `tmp_path`/`tmp_path_factory`.

## Чек-лист сценариев

Каждый тест покрывает хотя бы один пункт:

- Загрузка CSV и проверка обязательных колонок.
- Нормализация/предобработка (кодировки, разделители, дедупликация).
- Обогащение словарями, в том числе отсутствие совпадений.
- Правила трансформации и вычисления флагов.
- Обработка пропусков, дублей, конфликтов.
- Логирование WARN/ERROR при аномалиях.
- Финальная сборка (структура, сортировка, инварианты).
- Постобработка и экспорт (имена файлов, формат).
- Деградационные кейсы (частичные данные, пустые файлы, сломанные заголовки).
- Идемпотентность повторного запуска.

## Команды

- Быстрый цикл: `pytest -q -k "not slow and not e2e"`
- Полный прогон: `pytest -q`
- С покрытием: `pytest -q --cov=library --cov=scripts --cov-report=term-missing`

## Отчётность

```bash
pytest --json-report --json-report-file=reports/test_report.json
python tools/make_md_summary.py --input reports/test_report.json --output reports/test_summary.md
# пути можно не указывать, если используете значения по умолчанию (`python tools/make_md_summary.py` или `make-md-summary`)
```

JSON должен содержать блок `meta` с репозиторием, SHA, веткой, временем,
версиями Python/pytest. Markdown-отчёт повторяет таблицу из QA-руководства. При
успехе <95 % пайплайн должен падать.

## Работа с фейлами

- Детализированные ошибки правьте сразу или помечайте `xfail(strict=True)` со
  ссылкой на issue.
- Флейки запрещены — анализируйте и устраняйте причину.
- Для повторяющихся QA-сбоев создавайте issue с логами, артефактами и указанием
  конфигурации.
