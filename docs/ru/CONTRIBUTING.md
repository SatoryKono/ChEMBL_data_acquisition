# Руководство по вкладу

> **Языки:** [English](../../en/CONTRIBUTING.md) · Русский

## Политика закрепления зависимостей

- Рабочие зависимости (`[project.dependencies]`) фиксируются через совместимые спецификаторы версий (например, `~=`, `==`), которые ссылаются только на опубликованные релизы PyPI.
- Dev-набор (`[project.optional-dependencies].dev`) не должен ссылаться на неопубликованные или будущие фиктивные версии.
- Пакеты с typing stub должны указывать выпущенные сборки (например, `package==YYYY.MM.DD` либо нижнюю границу `package>=YYYY.MM.DD`) и не могут ссылаться на фиктивные будущие версии.
- При обновлении зависимостей запускайте `pip install .[dev]` локально или в CI, чтобы убедиться, что все объявленные экстры корректно резолвятся.
- После попадания обновлений зависимостей в основную ветку выполните `pip install -U .[dev]`, чтобы получить актуальные совместимые версии инструментов.
- Синхронизируйте `additional_dependencies` для хука `mypy` в `.pre-commit-config.yaml` с версиями из `pyproject.toml` и `requirements-lock.txt`. При необходимости обновить инструмент сначала скорректируйте ограничения в `pyproject.toml`, затем пересоберите `requirements-lock.txt`, и только после этого меняйте пины в конфигурации pre-commit.
- Зеркальте изменения между `[project.optional-dependencies].dev`, `requirements-dev.txt` и `requirements-lock.txt`, чтобы dev-окружение оставалось воспроизводимым. После правки списка экстр обновляйте lock-файл, чтобы новые пины распространились на все точки входа.
