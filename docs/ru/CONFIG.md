# Документация по `config.yaml`

Файл `config.yaml` управляет всеми CLI-скриптами и библиотеками проекта.
Любой параметр можно переопределить через флаг `--config`, аргументы командной
строки или переменные окружения вида `CHEMBL_DA__<SECTION>__<KEY>` (короткие
алиасы смотрите в `library/config.py`). Ниже приведено подробное описание
секций, типов значений и правил использования.

> **Важно:** секреты (токены, пароли, контактные e-mail) не хранятся в Git.
> Размещайте их в `.env`, менеджерах секретов или экспортируйте перед запуском:
> `export CHEMBL_DA__API__USER_AGENT="chembl-da/1.0 (mailto:you@org.org)"`.

## Блок: доступ к API

### `api`

| Ключ | Тип | Обязателен | Описание |
|------|-----|------------|----------|
| `chembl_base` | `str` | да | Базовый URL ChEMBL API. Пример: `https://www.ebi.ac.uk/chembl/api/data`. |
| `timeout_connect` | `int` | нет | Таймаут подключения в секундах; по умолчанию `5`. |
| `timeout_read` | `int` | нет | Таймаут ожидания ответа; по умолчанию `30`. |
| `retries` | `int` | нет | Количество повторных попыток при ошибках. |
| `backoff_factor` | `float` | нет | Множитель экспоненциальной паузы между повторами. |
| `rps` | `int` | нет | Лимит запросов в секунду для ChEMBL. |
| `burst` | `int` | нет | Допустимый размер «пакета» запросов в токен-бакете. |
| `user_agent` | `str` | да | Заголовок User-Agent с контактным e-mail. Требуется большинством API. |

### `chembl`

Параметры кэша при работе с ChEMBL API.

| Ключ | Тип | Обязателен | Описание |
|------|-----|------------|----------|
| `cache_ttl` | `int` | нет | TTL записей кэша в секундах (по умолчанию `3600`). |
| `cache_maxsize` | `int` | нет | Ограничение количества объектов в кэше. |

### `openalex`, `crossref`, `uniprot`, `uniprot_mapping`, `iuphar`, `pubchem`, `pubmed`, `semantic_scholar`

Каждый блок определяет параметры конкретного API. Типы аналогичны:

* `base` (`str`, обязателен) — базовый URL сервиса.
* `timeout_connect`, `timeout_read` (`int`) — таймауты сети.
* `retries` (`int`) — число попыток.
* `rps`, `burst` (`int`) — настройки rate limit (если поддерживаются).
* `delay`, `poll_interval` (`float`) — паузы между запросами (UniProt, PubChem).
* `mailto` (`str`, обязателен где требуется) — контактная почта согласно
  требованиям API (CrossRef, OpenAlex).
* `cache_ttl`, `cache_maxsize` (`int` | `null`) — параметры кэша для ID mapping.

Для `pubmed` fallback-кодировки (`utf-8-sig`, `cp1251`, `latin1`) зашиты в коде и
больше не настраиваются через `config.yaml`.

> **Совет:** значения по умолчанию подходят для публичных лимитов. При работе с
> приватными ключами/квотами увеличивайте `rps`, но не забудьте обновить
> `user_agent` и `mailto`.

## Блок: классификация документов

### `doc_type`

* `weights` — словарь весов (`dict[str, int]`) для источников (`pubmed`,
  `openalex`, `scholar`). Позволяет регулировать вклад каждого API в финальную
  классификацию.
* `thresholds` — пороги (`dict[str, int]`) для классов публикаций (`review`,
  `experimental`, `unknown`).
* `limit` — глобальное ограничение количества записей при отладке (`int | null`).

## Блок: параметры модулей

Каждый подпроект (`activity`, `assay`, `testitem`, `document`, `target`) имеет
настройки чтения входов и вызова API.

### `activity`

| Ключ | Тип | Обязателен | Описание |
|------|-----|------------|----------|
| `column` | `str` | да | Имя столбца с идентификаторами `activity_chembl_id` во входном CSV. |
| `chunk_size` | `int` | да | Размер пачки ID при запросах к API. |
| `timeout` | `float` | нет | Таймаут ожидания ответа от ChEMBL, секунды. |
| `limit` | `int | null` | нет | Ограничение числа записей для обработки. `null` — без лимита. |
| `dry_run` | `bool` | нет | Режим без сетевых вызовов/записи файлов. |

### `assay`

Аналогично `activity`, но для `assay_chembl_id`. Все ключи обязательны, кроме
`limit`.

### `testitem`

Чтение колонок `molecule_chembl_id` и контроль чанков/таймаутов.

### `document`

Блок разбит на под-разделы по источникам:

* `pubmed`: `column`, `sleep`, `workers`, `batch_size`, `limit` — управление
  мультипоточной загрузкой PubMed E-utilities.
* `chembl`: параметры для ChEMBL документов (колонка, `chunk_size`, `timeout`).
* `all`: общий агрегирующий конвейер (ID колонки, размер чанка, паузы,
  директории вывода). Если `chembl_out`/`uniprot_out`/`iuphar_out` заданы, они
  переопределяют пути к промежуточным CSV.

### `target`

* `uniprot`: исходная колонка `uniprot_id`, директория кэша (`data_dir`).
* `chembl`: параметры получения таргетов по `target_chembl_id`.
* `iuphar`: пути к справочникам IUPHAR.
* `all`: интегрированный пайплайн, объединяющий ChEMBL, UniProt и IUPHAR.
  Поддерживает переопределение путей результатов (`chembl_out` и др.) и размер
  чанков для сетевых вызовов.

## Блок: ресурсы и пути данных

### `resources`

Содержит базовые пути к словарям. Все параметры (`dictionary_dir`,
`iuphar_target_csv`, `iuphar_family_csv`, `uniprot_data_dir`, `organism_csv`,
`targets_type_csv`) — строки и обязательны при запуске конвейеров, которые ими
пользуются. Позволяет централизованно менять расположение справочников.

### `io`

| Ключ | Тип | Описание |
|------|-----|----------|
| `output_dir` | `str` | Папка для итоговых CSV/Parquet. Создаётся автоматически при `exist_ok: true`. |
| `cache_dir` | `str` | Каталог кэша HTTP-ответов. |
| `csv_sep` | `str` | Разделитель полей при записи CSV. |
| `csv_encoding` | `str` | Кодировка вывода (`utf-8-sig` по умолчанию). |
| `exist_ok` | `bool` | Разрешает создание директорий при записи файлов. |

### `init`

Пути к исходным XLSX для первичной инициализации документов. Используются
скриптом `get_input_initialisation.py`.

### `rate`

Глобальные параметры токен-бакета: `global_rps`, `global_burst`,
`limiter_cache_maxsize`, `limiter_cache_ttl`. Они применяются поверх
секционных лимитов и защищают от случайных шипов нагрузки.

## Настройка переменных окружения

* Формат: `CHEMBL_DA__<SECTION>__<KEY>` (два подчёркивания между секциями).
* Для вложенных блоков используйте полный путь: `CHEMBL_DA__DOCUMENT__PUBMED__SLEEP`.
* Короткие алиасы (`CHEMBL_DA_RPS`, `CHEMBL_DA_BASE` и т.д.) доступны для
  популярных параметров.

## Правила хранения чувствительных данных

1. Не коммитьте реальные токены/ключи в `config.yaml` или другие файлы
   репозитория.
2. Держите секреты в `.env`, недоступном Git (`.gitignore` уже включает файл).
3. При CI/CD используйте секреты пайплайна (GitHub Actions Secrets и т.п.).
4. Перед публикацией логов очищайте строки с авторизацией и параметры `user_agent`.

## Работа с альтернативными конфигурациями

* Для локальной отладки создайте копию `config.local.yaml` и передавайте её в
  `--config`.
* Используйте `library.config.ensure_dirs` для автоматического создания путей.
* Команда `python -m scripts.get_activity_data --print-config` выводит финальные
  значения с учётом переменных окружения и CLI-флагов.
