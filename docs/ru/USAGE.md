# Использование и справочник по CLI

Все точки входа доступны через `python scripts/<имя>.py` или как консольные
скрипты, устанавливаемые из `pyproject.toml` (`get-data`, `get-document-data`,
`get-target-data` и др.).

## Общие соглашения

| Опция | Описание |
|-------|----------|
| `--config` | Путь к YAML-конфигурации (по умолчанию `config/config.yaml`). |
| `--input` | CSV с идентификаторами. Если не указан, оркестратор строит путь из `--base-path` и `--input-dir`. |
| `--final-out` | Итоговый CSV. При отсутствии генерируется детерминированное имя `output.<stem>.csv` в каталоге вывода. Для добавления даты укажите `--date` или настройте `io.output_stamp_mode=require`. |
| `--sep`, `--encoding` | Разделитель и кодировка CSV (наследуются из конфигурации). |
| `--log-level` | Уровень логирования (`DEBUG`, `INFO`, `WARN`, `ERROR`). |
| `--verbose` | Включает логирование уровня DEBUG без изменения конфигурационных файлов. |
| `--run-id` | Переопределяет идентификатор запуска, который пишется в логи и sidecar-метаданные. По умолчанию вычисляется из вызова или берётся из переменной `CHEMBL_DA_RUN_ID`. |
| `--force` | Перезаписывать существующие файлы. |
| `--skip-existing` | Пропускать выполнение, если целевой файл уже существует. |
| `--limit`, `--offset` | Ограничение диапазона идентификаторов; `--limit 0` отключает конвейер. |
| `--print-config` | Вывести объединённую конфигурацию (дефолты + YAML + окружение + CLI) и завершить работу. |

> 💡 **Подсказка:** переменная окружения `CHEMBL_DA_RUN_ID` заполняет значение по
> умолчанию для `--run-id`, чтобы автоматизированные пайплайны писали стабильный
> идентификатор в логи и манифесты.

### Выходные артефакты

Каждый конвейер теперь оставляет минимальный набор рядом с итоговым CSV:

- `<stem>_quality_report_table.csv` — профиль таблицы из
  `library.table_quality.analyze_table_quality`.
- `<stem>_data_correlation_report_table.csv` — кросс-колоночные корреляции для
  QA-дашбордов.

Наследуемые диагностические файлы (`<stem>.meta.yaml`, `<stem>.quality.json`,
`<stem>_failure_cases.csv` и др.) подключаются по требованию через
`--emit-legacy-artifacts`, `--debug` или `--keep-intermediate`. Первый запуск
после обновления автоматически удалит устаревшие sidecar-файлы; при необходимости
повторите процедуру или выполните dry-run командой
`tools/cleanup_legacy_outputs.py`.

## Оркестратор `get-data`

Запуск всей цепочки с общими настройками:

```bash
python scripts/get_data.py \
  --base-path /data/chembl \
  --input-dir inbound \
  --output-dir outbound \
  --config config/config.yaml \
  --date 20250228 \
  --log-level INFO
```

Ключевые флаги:

**Базовые флаги запуска**

| Опция | Назначение | Когда использовать |
|-------|------------|--------------------|
| `--base-path`, `--input-dir`, `--output-dir` | Устанавливают общие каталоги ввода/вывода для всех пайплайнов. | Стандартизировать структуру окружений (smoke, QA, prod). |
| `--config` | Подключает альтернативный YAML-конфиг. | Указать окруженческие секреты или словари. |
| `--date` | Переопределяет префикс имени итоговых файлов. | Синхронизировать артефакты с отчётной датой или переиграть исторические дропы. |
| `--log-level`, `--verbose` | Управляют логированием; `--verbose` принудительно включает `DEBUG`. | Временно повысить подробность без правки конфигов. |
| `--limit` | Ограничивает количество идентификаторов на шаг (`0` пропускает выполнение). | Проводить детерминированные smoke/QA-прогоны. |
| `--force`, `--skip-existing` | Выбор между перезаписью и пропуском готовых шагов. | Возобновлять оборванные запуски без ручной очистки. |
| `--rerun-postprocess` | Пересобирает выравненные с этапами выгрузки даже при наличии кеша. | Обновить таблицы после правок постобработки. |
| `--dry-run` | Формирует и логирует план без файловых операций. | Проверить конфигурацию в CI или исследовательских блокнотах. |
| `--debug`, `--keep-intermediate` | Сохраняют промежуточные артефакты; `--debug` дополнительно включает подробные логи. | Исследовать внутренности пайплайнов при диагностике. |
| `--disable-pubchem` | Отключает обогащение PubChem на шаге testitem. | Изолировать проблемы enrichment или воспроизвести устаревший датасет. |
| `--print-config` | Выводит итоговую конфигурацию и завершает работу. | Зафиксировать параметры для ревью/аудита. |
| `--run-id` | Задаёт детерминированный идентификатор вместо вычисленного хэша. | Связать логи оркестратора с внешним планировщиком. |

Эти переключатели обрабатываются `_parse_args` и `PipelineRunConfig`, сохраняя канонический порядок шагов и проверки конфигурации.【F:library/cli/commands/get_data.py†L949-L1108】

### Расширенные переопределения

Используйте расширенные переопределения, когда нужно изменить план (частичные перезапуски, интеграционные тесты), а не для ежедневных запусков:

| Опция | Когда применять… |
|-------|------------------|
| `--pipeline-registry <path>` | Подключить альтернативный YAML-реестр, чтобы добавить/удалить шаги или изменить порядок. |
| `--override-input ШАГ=ФАЙЛ` | Подменить входной CSV для конкретного шага без правки реестра. |
| `--override-output-stem ШАГ=СТЕМ` | Перенаправить стем выходных файлов (и sidecar-артефактов) для одного шага. |
| `--override-subcommand ШАГ=ПОДКОМАНДА` | Запустить отличную подкоманду CLI, например `target=chembl` только для частичного прогона. |

Переопределения сохраняются в `PipelineRunConfig`, поэтому кастомные планы воспроизводят поведение CLI-вызова один в один.【F:library/cli/commands/get_data.py†L1048-L1108】

Оркестратор останавливается при первом ненулевом коде возврата и логирует время
выполнения каждого шага.

После каждого запуска формируется индивидуальный манифест вида
`reports/run_<timestamp>.json` относительно `--base-path`, а указатель
`reports/run_manifest.json` обновляется на последнюю попытку. В манифесте
фиксируются все шаги: путь к целевому CSV, обнаруженные sidecar-файлы, статус
(`success`, `skipped`, `failed`, `blocked` и т.д.), длительность и
SHA256-суммы артефактов. Файл создаётся даже при частичном выполнении, что
позволяет проанализировать промежуточные результаты. Если шаг завершился
ошибкой, все последующие помечаются как `blocked` с причиной
`dependency_failed`, чтобы явно отразить зависимость в манифесте.

### Частичный запуск документного шага

Чтобы перезапустить только документы, не затрагивая остальные этапы, зафиксируйте
нужный режим через `--override-subcommand` и при необходимости переименуйте
выходные файлы. Например, ChEMBL-часть:

```bash
python scripts/get_data.py \
  --base-path /data/chembl \
  --input-dir input --output-dir exports \
  --config /data/chembl/config.yaml \
  --date 20250101 \
  --override-subcommand document=chembl \
  --override-output-stem document=document_chembl
```

Аналогичный запуск в режиме PubMed меняет только одно значение:

```bash
python scripts/get_data.py \
  --base-path /data/chembl \
  --input-dir input --output-dir exports \
  --config /data/chembl/config.yaml \
  --date 20250101 \
  --override-subcommand document=pubmed \
  --override-output-stem document=document_pubmed
```

## Конвейер документов `get_document_data`

Режимы: `chembl`, `pubmed`, `all`.

Общие параметры:

| Опция | Значение по умолчанию | Примечание |
|-------|------------------------|------------|
| `--mode` | обязательно | Выбор сценария. |
| `--column` | Зависит от режима (`PMID` для `pubmed`, `document_chembl_id` в остальных случаях) | Колонка с идентификаторами. |
| `--limit`, `--offset` | `None`, `0` | Управление диапазоном. |
| `--timeout` | `90.0` (`chembl`/`all`), `10.0` (`pubmed`) | Таймаут HTTP-запросов. |
| `--openalex-rps`, `--crossref-rps` | `None` | Переопределение ограничений для партнёрских API при режимах `pubmed` или `all`. |

Флаги PubMed (`--mode pubmed` или `all`):

- `--batch-size` — количество идентификаторов на запрос (`100` для чистого
  `pubmed`, `50` в режиме `all`).
- `--sleep` — пауза между запросами (секунды).
- `--workers` — количество параллельных запросов.

Флаги ChEMBL (`--mode chembl` или `all`):

- `--chunk-size` — количество идентификаторов на запрос (по умолчанию `20`).
- `--chembl-chunk-size`, `--chembl-timeout` — переопределения для режима `all`.

Обработка резервных DOI:

| Опция | Назначение |
|-------|------------|
| `--fallback-doi-enabled` | Включить чтение резервного CSV. |
| `--fallback-doi-path` | Путь к CSV с DOI, привязанными к PMID. |
| `--fallback-doi-col-pmid`, `--fallback-doi-col-doi` | Названия колонок в CSV. |
| `--fallback-doi-delimiter`, `--fallback-doi-encoding` | Параметры парсинга CSV. |
| `--fallback-doi-overwrite` | Разрешить перезапись уже найденных DOI. |

Пример обогащения PubMed с резервными DOI:

```bash
python scripts/get_document_data.py --mode pubmed \
  --input data/input/document.csv \
  --final-out output/documents_pubmed.csv \
  --config config/config.yaml \
  --batch-size 50 \
  --sleep 3 \
  --workers 2 \
  --openalex-rps 3 --crossref-rps 3 \
  --fallback-doi-enabled \
  --fallback-doi-path data/input/document_fallback.csv
```

### Повторная постобработка

Добавьте `--rerun-postprocess`, если промежуточные стадии уже подготовлены, но
нужно заново собрать согласованные выгрузки. Флаг пересоздаёт постобработанные
артефакты даже при наличии предыдущих запусков. Совместное использование с
`--emit-legacy-artifacts` обновит как основную директорию вывода, так и
дополнительные legacy-CSV, а `--keep-intermediate` сохранит временные staging-
каталоги для диагностики.

## Конвейер таргетов `get_target_data`

Использует подкоманды: `uniprot`, `chembl`, `iuphar`, `all`.

Общие опции:

- Базовые флаги (`--input`, `--final-out`, `--verbose` и т.д.).
- `--raw-out`, `--raw-format` — сохранение промежуточного набора до нормализации
  (`csv` или `parquet`).
- `--id-cols` — колонки для детерминированной сортировки сырого набора.
- `--normalize-at-export` / `--no-normalize-at-export` — включение/отключение
  финальной нормализации перед экспортом.

### Подкоманды

#### `uniprot`

| Опция | Значение | Описание |
|-------|----------|----------|
| `--column` | `uniprot_id` | Колонка с UniProt-акцессиями. |
| `--chunk-size` | `100` | Размер батча для API или кеша. |
| `--timeout` | `30.0` | Таймаут запросов. |
| `--limit`, `--offset` | `None`, `0` | Диапазон записей. |
| `--data-dir` | из конфигурации | Каталог с кешированными `<accession>.json`. |

#### `chembl`

| Опция | Значение | Описание |
|-------|----------|----------|
| `--column` | `target_chembl_id` | Колонка с идентификаторами ChEMBL. |
| `--chunk-size` | `3` | Идентификаторов на запрос. |
| `--timeout` | `90.0` | Таймаут запросов. |

#### `iuphar`

| Опция | Значение | Описание |
|-------|----------|----------|
| `--column` | `uniprot_id` | Колонка для сопоставления UniProt→IUPHAR. |
| `--chunk-size` | `100` | Размер батча. |
| `--target-csv` | из конфигурации | Путь к `_IUPHAR_target.csv`. |
| `--family-csv` | из конфигурации | Путь к `_IUPHAR_family.csv`. |

#### `all`

Комбинирует три режима, позволяет сохранять промежуточные результаты и принимает
префиксные переопределения:

- `--chembl-out`, `--uniprot-out`, `--iuphar-out` — пути к промежуточным CSV.
- `--chembl-*`, `--uniprot-*`, `--iuphar-*` — переопределения `chunk-size`,
  `timeout`, `limit`, `offset` для каждого источника.
- `--uniprot-column` — колонка ChEMBL-выгрузки для получения UniProt-акцессий.

Пример:

```bash
python scripts/get_target_data.py all \
  --input data/input/target.csv \
  --final-out output/targets_20250228.csv \
  --config config/config.yaml \
  --chembl-out output/targets_chembl_raw.csv \
  --uniprot-out output/targets_uniprot_raw.csv \
  --iuphar-out output/targets_iuphar_raw.csv \
  --chembl-chunk-size 10 --uniprot-chunk-size 200
```

#### Пример для Windows (Command Prompt)

В командной строке Windows приглашение уже содержит путь
(`C:\\Users\\<вы>\\Documents\\GitHub\\ChEMBL_data_acquisition>`). После него вводите
только саму команду:

```cmd
py -3 scripts\get_target_data.py all ^
  --input data\input\target.csv ^
  --final-out data\output\targets_20251002.csv ^
  --limit 10
```

Символ `^` на конце строк необязателен, но помогает разбить длинную команду.
Используйте `--final-out`: прежние названия флага скрыты, доступен только
служебный алиас `--out` для обратной совместимости со старыми скриптами.

## Конвейер активностей `get_activity_data`

Расширяет параметры ассайев поддержкой ограничения диапазона, настройки
таймаутов, режима dry-run и параллельной загрузки. Помимо общих флагов (включая

| Опция | Значение по умолчанию | Описание |
|-------|-----------------------|----------|
| `--column` | `activity_id` | Колонка с идентификаторами активностей (конфигурация по умолчанию задаёт `activity_chembl_id`). |
| `--batch-size` | `5` | Количество идентификаторов в одном запросе (в конфигурации обычно увеличено до `20`). |
| `--timeout` | `90.0` | HTTP-таймаут на запрос. |
| `--limit`, `--offset` | `None`, `0` | Диапазон обработки; отрицательные значения запрещены. |
| `--workers` | `1` | Потоки для скачивания активностей. |
| `--dry-run` | `False` | Проверка без обращения к API и записи файлов. |

Пример: использование канонической колонки `activity_id` и нескольких потоков
для ускорения выгрузки.

```bash
python scripts/get_activity_data.py \
  --input data/input/activity.csv \
  --final-out output/activities_subset.csv \
  --column activity_id \

  --workers 4
```

Пост-обработка вычисляет `lower_value`/`upper_value` по алгоритму из
[`../OUTPUT.md`](../OUTPUT.md).

## Конвейер тканей `get_tissue_data`

Агрегирует метаданные тканей из ChEMBL и связанных онтологий, формируя
нормализованный справочник для последующих джойнов. В дополнение к базовым
флагам (например, `--verbose` для включения DEBUG) доступны опции:

| Опция | Значение по умолчанию | Описание |
|-------|-----------------------|----------|

| `--limit`, `--offset` | `None`, `0` | Ограничение диапазона до обращения к API. |

Пример, сохраняющий унифицированную таблицу и ограничивающий диапазон идентификаторов:

```bash
python scripts/get_tissue_data.py \
  --input data/input/tissue.csv \

  --config config/config.yaml \

  --limit 200 \
```

## Пайплайн клеточных линий `get_cellline_data`

Команда выгружает метаданные клеточных линий ChEMBL и приводит их к стабильной
схеме. Дополнительные параметры доступны помимо общих флагов (напоминаем,
`--verbose` включает DEBUG без изменения конфигурации):

| Опция | Значение по умолчанию | Описание |
|-------|-----------------------|----------|
| `--mode` | `chembl` | Использует ресурс ChEMBL `/cell_line`. |
| `--column` | `cell_chembl_id` | Колонка входного CSV с идентификаторами клеточных линий. |
| `--batch-size` | `20` | Количество идентификаторов в одном запросе. |
| `--timeout` | `30.0` | Таймаут HTTP-запроса в секундах. |
| `--limit`, `--offset` | `None`, `0` | Ограничение диапазона перед обращением к API. |

Пример: сохранить результат в отдельный файл и обработать только первые 25
строк входного CSV.

```bash
python scripts/get_cellline_data.py \
  --input data/input/cellline.csv \
  --final-out output/cellline.csv \
  --batch-size 10 \
  --limit 25
```

## Вспомогательные команды

Консольные скрипты из `library/utils/cli_tools`:

| Команда | Назначение |
|---------|------------|
| `check-determinism` | Сравнение хэшей CSV между запусками. |
| `table-quality` | Генерация профиля качества произвольной таблицы. |
| `csv-utils` | Детерминированные операции над CSV (сортировка, выбор колонок, хэш). |
| `mapper` | Интерактивное сопоставление UniProt↔ChEMBL на основе кешей. |
| `chunk-io` | Потоковая обработка CSV с сохранением порядка. |
| `get-input-initialisation` | Объединение Excel-шаблонов инициализации в канонический CSV. |
| `get-activities` | Создание синтетических активностей и детерминированных CSV + `.meta.yaml` для smoke-тестов. |
