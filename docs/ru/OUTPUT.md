# Выходные артефакты

В этом руководстве описываются файлы, создаваемые конвейерами сбора данных, их структура и модули, отвечающие за их создание.

## Стандартная структура каталогов

По умолчанию все экспорты записываются в каталог, указанный в `local.io.output_dir` в вашей конфигурации (обычно `~/.local/share/chembl-da/output`).

Стандартный запуск конвейера создает несколько файлов для каждого набора данных:

```
output/
├── output.activities_20240101.csv
├── output.activities_20240101.meta.yaml
├── output.activities_20240101_failure_cases.csv
└── output.activities_20240101_quality_report_table.csv
```

-   **`...csv`**: Основной файл данных, содержащий обработанные записи.
-   **`...meta.yaml`**: Файл метаданных-"сайдкар", который фиксирует контекст и статистику запуска конвейера.
-   **`..._failure_cases.csv`**: Отчет, содержащий строки, которые не прошли валидацию по схеме данных.
-   **`..._quality_report_table.csv`**: Отчет со статистикой на уровне столбцов и метриками качества.

## Объяснение основных артефактов

### 1. Детерминированные экспорты CSV

Основным результатом каждого конвейера является CSV-файл с детерминированной структурой. Функция `library.io.write_csv` гарантирует, что для одних и тех же входных данных и конфигурации выходной файл будет идентичным при разных запусках и в разных системах. Это достигается путем последовательной сортировки столбцов и строк перед записью.

### 2. Сайдкары метаданных (`*.meta.yaml`)

Каждый сгенерированный CSV-файл сопровождается файлом `.meta.yaml`. Этот сайдкар имеет решающее значение для воспроизводимости и содержит:

*   `generated_at`: Временная метка в формате ISO 8601 (UTC) создания файла.
*   `git_sha`: Хеш коммита кода, использованного для запуска.
*   `python_version`, `platform`: Детали среды выполнения.
*   `command`: Точная команда, использованная для запуска конвейера.
*   `config`: Действующие значения конфигурации с замаскированными секретами.
*   `inputs`: Описания исходных файлов и ключевых параметров.
*   `stats`: Словарь статистики, включая `rows_total`, `rows_kept`, `rows_dropped` и контрольную сумму `output_sha256` CSV-файла.
*   `schema`: Имя схемы валидации, примененной к данным.

### 3. Отчеты о валидации и качестве

*   **Случаи сбоя**: Если какие-либо строки в наборе данных не проходят валидацию по схеме Pandera (например, неверный тип данных, значение вне диапазона), они сохраняются в файл `_failure_cases.csv` для проверки.
*   **Качество таблицы**: Утилита `table-quality` (и большинство конвейеров) создает файл `_quality_report_table.csv` с подробной статистикой для каждого столбца (например, количество null-значений, уникальность, среднее, стандартное отклонение) и `_data_correlation_report_table.csv` для числовых столбцов.

## Специфичные для конвейера артефакты и столбцы

### Столбцы метаданных конвейера

Все экспортируемые таблицы включают два стандартных столбца метаданных:

*   `pipeline_version`: Версия пакета `chembl-data-acquisition`.
*   `timestamp_utc`: Временная метка UTC, отмечающая время начала запуска конвейера.

### Конвейер документов

*   **Столбцы классификации**: Этот конвейер добавляет несколько столбцов для классификации публикаций, включая `publication_class` (`review`, `experimental` или `unknown`) и оценки, использованные для ее определения.
*   **Отчет о качестве (`.quality.json`)**: В дополнение к стандартным файлам этот конвейер создает JSON-отчет, суммирующий покрытие DOI и любые ошибки, возникшие при получении данных из вышестоящих сервисов.

### Конвейер активностей

*   **Производные границы**: Конвейер вычисляет столбцы `lower_value` и `upper_value` из стандартных столбцов активности ChEMBL (`standard_value`, `standard_relation` и т.д.), чтобы предоставить канонический диапазон для значений активности. Это контролируется конфигурацией `activity_bounds`.
*   **Столбцы обогащения**: На основе конфигурации `activity_enrichment` конвейер может добавлять столбец `action_type` (например, `inhibition`, `activation`) и столбец `properties_hash`.

### Конвейер мишеней

*   **Промежуточные экспорты**: Это единственный конвейер, который в настоящее время поддерживает отдельную выгрузку "сырых" данных через аргумент `--raw-out`. Это позволяет проверять данные перед заключительными этапами нормализации и валидации.

### Конвейер тестовых образцов

*   **Обогащенные данные**: Вывод включает столбцы, обогащенные данными из PubChem (например, `pubchem_cid`, `pubchem_iupac_name`) и информацией о родительских молекулах, полученной из каталога молекул (`parent_molecule_chembl_id`).
