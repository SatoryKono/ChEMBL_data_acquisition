# Схема конфигурации пайплайнов

> **Languages:** [English](../en/architecture/PIPELINE_CONFIG_SCHEMA.md) · Русский

Все CLI пайплайнов используют декларативные метаданные, хранящиеся в `config/pipeline/`.
Каждый файл `<table>.yaml` описывает поведение соответствующего CLI: какие
этапы включены, параметры конфигурации, которые могут быть переопределены из
командной строки, ожидаемые входы/выходы и колонки метаданных, добавляемые к
экспортам. Файлы обрабатываются функцией
`library.pipelines.configuration.load_pipeline_config`, которая возвращает
dataclass'ы `PipelineConfig` для последующих инструментов.

```pycon
>>> from library.pipelines.configuration import load_pipeline_config
>>> cfg = load_pipeline_config("activity")
>>> cfg.name
'activity'
>>> cfg.parameters.mapping_for()
{'column': 'activity.column', 'batch_size': 'activity.batch_size', ...}
```

Загрузчик автоматически разрешает версию установленного пакета, когда файл использует
`pipeline_version: value: auto` и предоставляет удобные помощники для объединения
маппингов параметров по режиму/команде.

## Ключи верхнего уровня

| Ключ                | Тип                          | Описание |
|--------------------|-------------------------------|----------|
| `name`             | string                        | Канонический идентификатор пайплайна. По умолчанию используется имя файла без расширения, если не указано. |
| `summary`          | string (опционально)          | Человекочитаемое описание, используемое в документации и диагностике. |
| `schemas`          | mapping                       | Маппинг варианта → имя Pandera схемы, применяемой к экспорту. Используйте `default`, когда пайплайн имеет одну схему. |
| `pipeline_version` | string или mapping            | Описывает колонку метаданных, добавляемую к экспортам. Принимает либо имя колонки (`pipeline_version: pipeline_version`), либо маппинг с `column`, опциональным `description` и опциональным `value`. Загрузчик разрешает `value: auto` до версии установленного пакета. |
| `inputs`           | mapping (опционально)         | Объявляет входные артефакты. Распознаваемые ключи: `primary` (string) и `dependencies` (list of strings). Дополнительные ключи сохраняются дословно в `PipelineIO.variants`. |
| `outputs`          | mapping (опционально)         | Объявляет выходные артефакты, используя ту же структуру, что и `inputs`. Общие варианты включают `modes`/`commands` для многоэтапных пайплайнов и `artefacts` для sidecar'ов. |
| `parameters`       | mapping (опционально)         | Маппит CLI опции к путям конфигурации. Принимает встроенные пары ключ/значение для значений по умолчанию и вложенные маппинги под `default`, `shared`, `modes` и `commands`. |
| `steps`            | sequence (опционально)        | Упорядоченный список, описывающий логические этапы пайплайна. Каждая запись — это маппинг, описанный ниже. |

### Маппинги параметров

Секция `parameters` поддерживает четыре группы:

- Встроенные пары ключ/значение или маппинг `default` для опций, общих для всех
  вариантов.
- `shared`: применяется дополнительно к значениям по умолчанию для каждого варианта.
- `modes`: маппинг имени режима → параметры. Используется пайплайном документов.
- `commands`: маппинг имени подкоманды → параметры. Используется пайплайном таргетов.

Загрузчик предоставляет помощники `PipelineParameters.mapping_for(mode="all")` и
`PipelineParameters.mapping_for(command="chembl")` для объединения
соответствующих словарей.

### Записи этапов

Каждая запись `steps` может определять следующие ключи:

| Ключ           | Тип                | Описание |
|---------------|---------------------|----------|
| `name`        | string              | Идентификатор этапа. |
| `description` | string (опционально) | Человекочитаемая сводка, показываемая в документации и манифестах. |
| `enabled`     | bool/string (опционально) | При наличии переопределяет значение по умолчанию `True`. Значения, отличные от явного `false`/`0`/`no`, считаются включёнными. |
| `depends_on`  | list of strings (опционально) | Объявляет вышестоящие этапы, которые должны завершиться перед запуском этого этапа. |
| `produces`    | list of strings (опционально) | Объявляет артефакты, создаваемые этапом. |
| `applies_to`  | string или list of strings (опционально) | Ограничивает этап конкретными режимами/командами (например, `chembl`, `pubmed`, `all`). |

Этапы позволяют последующим инструментам (например, оркестратору) отображать более
ясные планы выполнения без жёсткого кодирования описаний.

## Добавление нового определения пайплайна

1. Создайте `config/pipeline/<name>.yaml`, следуя структуре выше.
2. Заполните `schemas` Pandera схемами, используемыми CLI.
3. Объявите колонку `pipeline_version`. Используйте `value: auto` для разрешения
   текущей версии пакета во время выполнения.
4. Перечислите параметры CLI по умолчанию и специфичные для вариантов под `parameters`, чтобы
   автоматизация могла строить точные маппинги переопределения конфигурации.
5. Опишите логические этапы, выполняемые пайплайном, под `steps`.
6. Обновите или добавьте unit-тесты, покрывающие `library.pipelines.configuration`, если вы
   вводите новые ключи, чтобы регрессии схемы обнаруживались рано.

Обратитесь к существующим файлам, таким как `config/pipeline/activity.yaml` и
`config/pipeline/document.yaml`, для конкретных примеров.
