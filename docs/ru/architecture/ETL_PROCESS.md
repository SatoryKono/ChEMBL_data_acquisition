# ETL-процесс

ETL-поток одинаков для обеих языковых версий. Ниже описаны шаги внутри каждого
конвейера.

## 1. Документы

1. Чтение входного CSV (`--input`) и проверка колонок (`document_chembl_id`,
   колонка идентификаторов в зависимости от режима).
2. Стадия **ChEMBL** (`mode=chembl`): пакетные запросы к API, объединение
   результатов, нормализация DOI и авторов, фиксация статусов.
3. Стадия **PubMed** (`mode=pubmed`): батчирование PMID, вызовы PubMed, Semantic
   Scholar, OpenAlex, CrossRef с учётом лимитов, объединение JSON-ответов.
4. Стадия **all**: слияние, применение CSV-фолбэков по DOI, дедупликация по DOI/PMID.
5. Постобработка: расчёт класса публикации, оценок review, запись CSV и артефактов качества.

## 2. Таргеты

1. Чтение CSV с `target_chembl_id` и опциональными UniProt колонками.
2. **ChEMBL**: получение базовых данных, кросс-ссылок и классификаций.
3. **UniProt**: загрузка кэшированных или свежих JSON, извлечение последовательностей,
   GO, топологии, PTM.
4. **IUPHAR**: сопоставление UniProt→IUPHAR по локальным словарям.
5. Объединение стадий, нормализация по `TARGETS_COLUMN_ORDER`, валидация Pandera, экспорт.

## 3. Ассайи

1. Проверка колонок (`assay_chembl_id`, `target_chembl_id`).
2. Получение метаданных из ChEMBL (BAO, флаги корреляций, ссылки на документы).
3. Приведение типов, добавление метаданных пайплайна, выгрузка CSV и сайдкары.

## 4. Тестовые объекты

1. Проверка `molecule_chembl_id`.
2. Загрузка данных ChEMBL: структура, способы введения, предупреждения.
3. Обогащение PubChem (порядок: кэш → SMILES → InChIKey → InChI → имя).
4. Согласование родителей по словарям, предупреждения при отсутствии записей,
   использование иерархии при `parent_fallback=true`.
5. Экспорт с приведением булевых значений и метаданными.

## 5. Активности

1. Проверка `activity_chembl_id`, `assay_chembl_id`, `molecule_chembl_id`.
2. Пакетная загрузка активностей ChEMBL с учётом `--workers`.
3. Нормализация колонок `standard_*`, расчёт границ по `relation`, вычисление
   `action_type` и разворачивание `activity_properties`.
4. Проверка `standard_value >= 0`, соответствия `action_type` allowlist, экспорт и QC.

## Общая постобработка

- Детерминированная сортировка по идентификаторам.
- Упорядочивание колонок через константы (`DOCUMENT_SCHEMA_COLUMNS`, `TARGETS_COLUMN_ORDER`, ...).
- Генерация `.meta.yaml`, `.quality.json` и таблиц качества.
- Настройка профиля качества через `system.doc_quality`.

Дополнительно см. [`QC_DEPENDENCIES.md`](./QC_DEPENDENCIES.md) и
[`DATA_MODEL.md`](./DATA_MODEL.md).
