# Утилиты для получения данных из ChEMBL

Этот репозиторий содержит набор утилит на Python для извлечения, обработки и обогащения данных из базы данных ChEMBL и других связанных ресурсов в области наук о жизни, таких как UniProt, IUPHAR, PubMed и PubChem.

|----------|--------------------|
| English  | [`../en/README.md`](../en/README.md) |
| Русский  | [`README.md`](./README.md) |

Вся документация поддерживается в синхронизированных английской и русской версиях.

## Ключевые особенности

- **Конвейеры данных:** Комплексные конвейеры для документов, таргетов, ассеев, активностей и тестовых образцов.
- **Оркестратор:** Высокоуровневый оркестратор (`get-data`) для последовательного запуска всех конвейеров с общей конфигурацией.
- **Единый CLI:** Согласованный интерфейс командной строки с общими флагами для ввода-вывода, конфигурации и логирования.
- **Гибкая конфигурация:** Настройка через YAML-файлы, переменные окружения и аргументы командной строки.
- **Контроль качества:** Встроенная валидация схем, детерминированная запись CSV, статический анализ и модульные тесты для обеспечения качества и воспроизводимости данных.

## Быстрый старт

1.  **Создайте виртуальное окружение и установите зависимости:**

    ```bash
    python -m venv .venv
    source .venv/bin/activate  # В Windows используйте: .venv\Scripts\activate
    pip install -r requirements-lock.txt
    ```

2.  **Инициализируйте pre-commit хуки:**

    ```bash
    pre-commit install
    ```

3.  **Изучите главный скрипт-оркестратор:**

    Запустите главный скрипт `get-data` с флагом `--help`, чтобы увидеть все доступные опции.

    ```bash
    get-data --help
    ```

## Конвейер таргетов

CLI `get-target-data` предлагает четыре режима получения данных (`chembl`, `uniprot`, `iuphar`, `all`). Теперь каждый режим поддерживает единый набор флагов для выбора и пагинации:

- `--column`: колонка входного CSV с идентификаторами.
- `--chunk-size`: размер батча для обращений к API или чтения из кеша.
- `--timeout`: таймаут сетевых операций в секундах.
- `--limit`: верхняя граница по количеству обрабатываемых строк; отсутствие флага означает обработку всего CSV.
- `--offset`: число строк, пропускаемых перед началом обработки.

Объединённый режим `all` пробрасывает эти значения во вложенные конвейеры и позволяет переопределять параметры отдельных источников через префиксованные флаги (например, `--chembl-chunk-size`, `--uniprot-timeout`). При запуске скрипт логирует итоговые значения и источник каждого параметра (значения по умолчанию, YAML-конфигурация или CLI), что упрощает диагностику.

Подробные примеры доступны в [`docs/ru/USAGE.md`](./USAGE.md), а соответствующие ключи конфигурации описаны в [`docs/ru/reference/CONFIG.md`](./reference/CONFIG.md).

## Пайплайн документов

Запускайте документный конвейер через единый вход `python scripts/get_document_data.py --mode <chembl|pubmed|all>`. Значение `--mode` определяет, какие стадии выполняются, при этом общие флаги CLI остаются едиными и описаны в руководстве по использованию.

| Значение `--mode` | Назначение | Пространственные флаги |
|-------------------|------------|------------------------|
| `chembl` | Выгружает метаданные документов из ChEMBL. | `--chembl-chunk-size`, `--chembl-timeout` (либо общие `--chunk-size`, `--timeout`). |
| `pubmed` | Обогащает данные через PubMed, Semantic Scholar, OpenAlex и CrossRef. | `--pubmed-sleep`, `--pubmed-workers`, `--pubmed-batch-size`, `--openalex-rps`, `--crossref-rps`. |
| `all` | Последовательно выполняет этапы `chembl` и `pubmed`, затем объединяет результаты. | Принимает оба набора пространственных флагов и параметры DOI-фолбэков. |

Примеры:

```bash
# Только ChEMBL
python scripts/get_document_data.py --mode chembl \
    --input data/input/document.csv \
    --final-out output/documents_chembl.csv \
    --config config/config.yaml

# PubMed и партнёрские сервисы
python scripts/get_document_data.py --mode pubmed \
    --input data/input/document.csv \
    --final-out output/documents_pubmed.csv \
    --config config/config.yaml \
    --openalex-rps 3 --crossref-rps 3

# Полный прогон с ручными DOI
python scripts/get_document_data.py --mode all \
    --input data/input/document.csv \
    --final-out output/documents_full.csv \
    --config config/config.yaml \
    --fallback-doi-enabled \
    --fallback-doi-path data/input/document_fallback.csv \
    --fallback-doi-overwrite
```

На выходе формируется детерминированный CSV, `<имя>.meta.yaml`, отчёты `<имя>_quality_report_table.csv`, `<имя>_data_correlation_report_table.csv` и файл `<имя>.quality.json` со статистикой по DOI.
