### Обязательные команды CI

В непрерывной интеграции всегда запускаются следующие команды (в указанном
порядке). Изменения в пайплайне должны поддерживать их успешное выполнение и
детерминированные артефакты отчётности:

1. `python scripts/run_tests.py` — pytest + генерация `reports/test_report.json`
   и `reports/test_summary.md` с проверкой порога **95 %** успешных тестов.
2. `ruff check` — статический анализ кода, ошибок форматирования и импорта.
3. `mypy --strict library` — строгая проверка типизации основной кодовой базы.

### Детали сбоя
- `tests/unit/test_cli_get_document_data.py` падает на стадии импорта: в `scripts/get_document_data.py` отсутствует `import argparse`, и класс `_FallbackPathAction` использует `argparse.Action`. Pytest прекращает работу сразу после обнаружения ошибки `NameError`.

### Примечания
- Линтер фиксирует 52 ошибки: массовые нарушения `I001` из-за вставленных «слэш»-маркеров перед `import`, а также `F821` для пропущенных `import os/argparse` в CLI-скриптах. Без очистки линтер прерывает процесс на первых модулях (`library/cli/commands/get_document_data.py`, `scripts/get_document_data.py`).

- Для разблокировки strict-режима необходимо вернуть потерянные импорты, переписать «размороженные» `object`/`Any` в CLI-стэках, нормализовать использование `pandas.isna` и добавить заглушки для `_bootstrap`, `library.rate_limiter` и вспомогательных модулей.

## Как обновить отчёт

1. Активировать окружение: `source .venv/bin/activate`.
2. Сгенерировать отчёты:
   ```bash
   python scripts/run_tests.py
   ruff check > ruff-report.txt
   mypy --strict library > mypy-report.txt
   ```
3. Перенести обновлённые значения в эту страницу.
