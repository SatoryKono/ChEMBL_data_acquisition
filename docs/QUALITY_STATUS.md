### Обязательные команды CI

В непрерывной интеграции всегда запускаются следующие команды (в указанном
порядке). Изменения в пайплайне должны поддерживать их успешное выполнение и
детерминированные артефакты отчётности:

1. `python scripts/run_tests.py` — pytest + генерация `reports/test_report.json`
   и `reports/test_summary.md` с проверкой порога **95 %** успешных тестов.
2. `pytest -q` — минимальный smoke-прогон без отключения предупреждений.
3. `ruff check` — статический анализ кода, ошибок форматирования и импорта.
4. `mypy --strict library` — строгая проверка типизации основной кодовой базы.
5. `pre-commit run --all-files` — консистентная обвязка локальных и CI-проверок.

Дополнительно пайплайн запускает smoke-тест установки на Python 3.13
(`pip install .`), чтобы убедиться, что маркерная зависимость `pyarrow`
пропускается и проект ставится без сборки нативных колёс.

### Детали сбоя
- `python scripts/run_tests.py` падает до запуска тестов: `pytest` не понимает флаги покрытия без установленного `pytest-cov`, прерывается с кодом 4 и оставляет success rate на уровне 0 %.【2abddb†L1-L13】【F:reports/test_summary.md†L5-L20】

## Регламент актуализации

1. После каждого релиза и при значимых изменениях пайплайна запускать полный набор обязательных команд CI, фиксируя вывод в QA-отчёте (`reports/test_report.json` и краткая сводка в `reports/test_summary.md`).
2. Проверять наличие актуальных отчётов в каталоге `reports/tests/` и добавлять ссылку на свежий документ в раздел «Статический отчёт о качестве».
3. Обновлять таблицы статусов и раздел «Риски» на основании последних прогонов; если проблема устранена, переносить запись в архив либо удалять из текущего файла.
4. При установке зависимостей следить за совместимостью версий с текущим Python: `types-pytest` и связанные пакеты требуют выпусков, поддерживающих Python 3.11. С 2025-10-11 зависимость ограничена маркером `python_version < "3.11"`; с 2025-12-05 `pyarrow` дополнительно ограничен маркером `python_version < "3.13"`, чтобы установки на Python 3.13 проходили без сборки исходников. Smoke-тест в CI проверяет, что `pip install .` завершает работу успешно, а пайплайн при отсутствии `pyarrow` использует `fastparquet` или NumPy-бэкенд. При обновлении стубов и бэкендов фиксируйте результат в этом разделе и синхронизируйте lock-файлы.【145da3†L1-L12】【6599c7†L1-L12】
5. Поддерживать ссылку на используемое окружение (venv/conda) и контрольный список действий в этом разделе; перед публикацией PR сверять документ с фактическими логами CI.

## Как обновить отчёт

1. Активировать окружение: `source .venv/bin/activate`.
2. Сгенерировать отчёты:
   ```bash
   python scripts/run_tests.py
   ruff check > ruff-report.txt
   mypy --strict library > mypy-report.txt
   ```
3. Перенести обновлённые значения в эту страницу.

## Риски

- **Отсутствие плагина `pytest-cov` блокирует `scripts/run_tests.py`.** После установки только `pytest-json-report` команда не находит `pytest-cov`, не распознаёт флаги покрытия и завершается с кодом 4, из‑за чего отчётность и success rate в CI обнуляются.【2abddb†L1-L13】【F:reports/test_summary.md†L5-L20】
- **Smoke-прогон `pytest -q --disable-warnings` зависит от dev-зависимостей.** Без `freezegun`, `hypothesis`, `responses` тестовый раннер останавливается ещё на этапе импорта и не покрывает ключевые сценарии пайплайна.【0c4395†L1-L31】
- **Линтер и строгая типизация фиксируют крупный технический долг.** `ruff` сообщает об импортных конфликтах и неиспользуемых символах, а `mypy` — о сотнях несогласованных типов и отсутствии stubs, что блокирует включение этих проверок в CI.【82bf11†L1-L10】【2d2413†L1-L4】
