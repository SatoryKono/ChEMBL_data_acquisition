### Обязательные команды CI

В непрерывной интеграции всегда запускаются следующие команды (в указанном
порядке). Изменения в пайплайне должны поддерживать их успешное выполнение и
детерминированные артефакты отчётности:

1. `python scripts/run_tests.py` — pytest + генерация `reports/test_report.json`
   и `reports/test_summary.md` с проверкой порога **95 %** успешных тестов.
2. `pytest -q` — минимальный smoke-прогон без отключения предупреждений.
3. `ruff check` — статический анализ кода, ошибок форматирования и импорта.
4. `mypy --strict library` — строгая проверка типизации основной кодовой базы.
5. `pre-commit run --all-files` — консистентная обвязка локальных и CI-проверок.

### Детали сбоя
- `python scripts/run_tests.py` завершается до инициализации pytest: модуль `library` не находится в `sys.path`, поэтому bootstrap тестового контура не выполняется.【e8d59a†L1-L4】
- При прямом запуске `pytest -q` импорт `tests/conftest.py` прерывается отсутствующей зависимостью `numpy`, что блокирует весь тестовый набор.【438e77†L1-L5】

## Регламент актуализации

1. После каждого релиза и при значимых изменениях пайплайна запускать полный набор обязательных команд CI, фиксируя вывод в QA-отчёте (`reports/test_report.json` и краткая сводка в `reports/test_summary.md`).
2. Проверять наличие актуальных отчётов в каталоге `reports/tests/` и добавлять ссылку на свежий документ в раздел «Статический отчёт о качестве».
3. Обновлять таблицы статусов и раздел «Риски» на основании последних прогонов; если проблема устранена, переносить запись в архив либо удалять из текущего файла.
4. При установке зависимостей следить за совместимостью версий с текущим Python: `types-pytest` и связанные пакеты требуют выпуски, поддерживающие Python 3.11. С 2025-10-11 зависимость ограничена маркером `python_version < "3.11"`, поэтому `pip install -r requirements-dev.txt` на Python 3.11.12 завершился успешно; при обновлении стубов необходимо вернуть совместимую версию и задокументировать результат.【145da3†L1-L12】【6599c7†L1-L12】
5. Поддерживать ссылку на используемое окружение (venv/conda) и контрольный список действий в этом разделе; перед публикацией PR сверять документ с фактическими логами CI.

## Как обновить отчёт

1. Активировать окружение: `source .venv/bin/activate`.
2. Сгенерировать отчёты:
   ```bash
   python scripts/run_tests.py
   ruff check > ruff-report.txt
   mypy --strict library > mypy-report.txt
   ```
3. Перенести обновлённые значения в эту страницу.

## Риски

- **Зависимости тестового контура не подготовлены.** Без модулей `library`, `numpy` и `pydantic` прерываются `python scripts/run_tests.py`, `pytest` и `mypy`, поэтому success rate не рассчитывается; необходимо устанавливать пакет в editable-режиме и dev-зависимости перед прогоном.【e8d59a†L1-L4】【438e77†L1-L5】【c8d83b†L1-L4】
- **Линтер фиксирует массовые нарушения.** Несортированные импорты и устаревшие `noqa`-коды приводят к 132 ошибкам `ruff`, что блокирует автоматический формат и препятствует запуску хуков.【27ea81†L1-L14】
- **Dev-зависимости конфликтуют с Python 3.11.** Пакет `types-pytest` недоступен для текущей версии интерпретатора, поэтому установка dev-набора обрывается; требуется обновить требования либо заменить пакет.【52ce31†L1-L24】
- **Хуки pre-commit не задействованы.** Утилита отсутствует в окружении, из-за чего форматирование и локальные проверки не запускаются автоматически.【f6f525†L1-L3】
