### Обязательные команды CI

В непрерывной интеграции всегда запускаются следующие команды (в указанном
порядке). Изменения в пайплайне должны поддерживать их успешное выполнение и
детерминированные артефакты отчётности:

1. `python scripts/run_tests.py` — pytest + генерация `reports/test_report.json`
   и `reports/test_summary.md` с проверкой порога **95 %** успешных тестов.
2. `pytest -q` — минимальный smoke-прогон без отключения предупреждений.
3. `ruff check` — статический анализ кода, ошибок форматирования и импорта.
4. `mypy --strict library` — строгая проверка типизации основной кодовой базы.
5. `pre-commit run --all-files` — консистентная обвязка локальных и CI-проверок.

### Детали сбоя
- `python scripts/run_tests.py` завершается до инициализации pytest: модуль `library` не находится в `sys.path`, поэтому bootstrap тестового контура не выполняется.【d4c3fe†L1-L5】
- При прямом запуске `pytest -q` импорт `tests/conftest.py` прерывается отсутствующей зависимостью `numpy`, что блокирует весь тестовый набор.【67edd5†L1-L5】

## Как обновить отчёт

1. Активировать окружение: `source .venv/bin/activate`.
2. Сгенерировать отчёты:
   ```bash
   python scripts/run_tests.py
   ruff check > ruff-report.txt
   mypy --strict library > mypy-report.txt
   ```
3. Перенести обновлённые значения в эту страницу.

## Риски

- **Зависимости тестового окружения не установлены.** Без модулей `library`, `numpy` и `pydantic` не запускаются `python scripts/run_tests.py`, `pytest` и `mypy`, а success rate не подлежит расчёту. Требуется настроить `PYTHONPATH` и установить dev-зависимости перед любыми измерениями.【d4c3fe†L1-L5】【67edd5†L1-L5】【3ea301†L1-L4】
- **Линтер блокируется на структуре CLI.** Ошибки `I001`, `B010` и `F811` в файлах `library/cli` и `scripts/_postprocess_common.py` указывают на незавершённый рефакторинг; пока импорты и дубли типов не исправлены, линтер не даст зелёный статус и будет срывать `pre-commit`.【7c041c†L1-L170】
- **Отсутствует единая точка запуска проверок.** Команда `pre-commit run --all-files` недоступна из-за отсутствующей утилиты, что повышает риск рассинхрона между локальными и CI-проверками. Нужно закрепить установку `pre-commit` в инструкциях разработчика и CI job'е.【e26672†L1-L3】
