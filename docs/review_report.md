# Отчёт по ревью ChEMBL_data_acquisition

## Проверки
- `pytest -q --disable-warnings` — **ошибка импорта** из-за синтаксической ошибки в `scripts/check_determinism.py`.
- `mypy library scripts` — **1 ошибка** (синтаксический сбой в `scripts/check_determinism.py`).
- `ruff check .` — **998 ошибок** (в основном по стилю импорта, ошибкам F821 и пр.).
- `pre-commit run --all-files` — команда недоступна (не установлен pre-commit в окружении).

## Оценка категорий
| Категория | Балл | Комментарий |
|-----------|------|-------------|
| Structure | 3/5 | Богатая структура модулей и конфигурации, но есть хрупкие CLI-утилиты, завязанные на `sys.path` и ручные bootstrap-хаки. |
| Config    | 4/5 | Единый `config/config.yaml` с подробными комментариями и типизированной загрузкой через Pydantic, но нет явной фиксации версии пайплайна в `.meta`. |
| Quality   | 2/5 | Масштабный долг по линтингу (`ruff` 998 ошибок), отдельные тесты используют небезопасные конструкции, нарушающие статический анализ. |
| Errors    | 2/5 | Критическая синтаксическая ошибка в `scripts/check_determinism.py`, отсутствуют проверки генерации отчётов при сбоях CLI-скриптов. |
| Perf      | 3/5 | Пайплайны используют чанкинг и rate limiter, но профилировщик и вспомогательные скрипты опираются на полный импорт `pandas`, что мешает лёгким проверкам. |
| Testing   | 3/5 | Богатая тестовая матрица, но базовые проверки не проходят из-за синтаксической ошибки и долга по линтеру; отчёты не генерируются автоматически. |
| Docs      | 3/5 | Много README и комментариев, но отсутствует живой статус по качеству и инструкции по устранению долгов.

## Детали по категориям
### Structure
- Положительно: модуль `library/config/models.py` предоставляет типизированные модели с валидацией, покрывая alias-ENV схему.【F:library/config/models.py†L1-L140】
- Риск: несколько CLI-скриптов (`tools/make_md_summary.py`, `tools/profile_activity_pipeline.py`) модифицируют `sys.path`, что ломает инкапсуляцию и усложняет упаковку.【F:tools/make_md_summary.py†L1-L24】【F:tools/profile_activity_pipeline.py†L1-L18】

### Config
- Конфигурация централизована, подробно документирована и использует переменные окружения с алиасами.【F:config/config.yaml†L1-L122】
- Нет артефакта версии пайплайна (`.meta.yaml` или аналог) в каталоге данных, что усложняет воспроизводимость.

### Quality
- Статический анализ не проходит: `scripts/check_determinism.py` содержит синтаксическую ошибку, а тесты используют небезопасные аннотации, провоцирующие F821.【F:scripts/check_determinism.py†L154-L205】【F:tests/unit/tools/test_run_tests.py†L296-L318】
- Линтер `ruff` выдаёт 998 ошибок, включая проблемы уровня F (runtime), что отражает большой технический долг.【e24ed4†L1-L137】

### Errors
- CLI `scripts/check_determinism.py` из-за ошибочного дублирования `sys.stderr.write(` не компилируется и срывает smoke-тесты детерминизма.【F:scripts/check_determinism.py†L154-L162】
- Обработка отсутствующих файлов в `tools/make_md_summary.py` завязана на `RuntimeError`, но импорт `scripts.run_tests` произойдёт до проверки входных аргументов и упадёт, если структура проекта изменится или скрипт запускают из установленного пакета.【F:tools/make_md_summary.py†L1-L24】

### Perf
- Основные пайплайны используют rate limiter и чанкинг в конфигурации, что помогает масштабируемости.【F:config/config.yaml†L10-L104】
- Профилировочный скрипт жёстко тянет `pandas` и тяжёлые зависимости через `sys.path`, хотя сам профилировщик мог бы работать с CSV-заглушками и lazy-импортами.【F:tools/profile_activity_pipeline.py†L1-L46】

### Testing
- Тестовая инфраструктура богата (unit/integration/e2e), фикстура `deterministic_env` хорошо фиксирует окружение.【F:tests/conftest.py†L35-L158】
- Однако базовый прогон pytest не стартует из-за синтаксической ошибки и не может подтвердить детерминизм CLI; также отчёт `reports/test_summary.md` не генерируется при падении тестов.【f0dcea†L1-L23】

### Docs
- Имеются локализованные README, но нет статуса CI и инструкций по устранению текущих блокеров.
