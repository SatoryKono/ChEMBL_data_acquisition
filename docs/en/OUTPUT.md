# Output Artifacts

This guide describes the files generated by the data acquisition pipelines, their structure, and the modules responsible for creating them.

## Standard Directory Layout

By default, all exports are written to the directory specified by `local.io.output_dir` in your configuration (typically `~/.local/share/chembl-da/output`).

A standard pipeline run generates several files for each dataset:

```
output/
├── output.activities_20240101.csv
├── output.activities_20240101.meta.yaml
├── output.activities_20240101_failure_cases.csv
└── output.activities_20240101_quality_report_table.csv
```

-   **`...csv`**: The main data file containing the processed records.
-   **`...meta.yaml`**: A metadata "sidecar" file that captures the context and statistics of the pipeline run.
-   **`..._failure_cases.csv`**: A report containing rows that failed validation against the data schema.
-   **`..._quality_report_table.csv`**: A report with column-level statistics and quality metrics.

## Core Artifacts Explained

### 1. Deterministic CSV Exports

The primary output of each pipeline is a CSV file with a deterministic structure. The `library.io.write_csv` function ensures that for the same input data and configuration, the output file will be identical across different runs and systems. It achieves this by sorting columns and rows in a consistent manner before writing.

### 2. Metadata Sidecars (`*.meta.yaml`)

Every generated CSV is accompanied by a `.meta.yaml` file. This sidecar is crucial for reproducibility and contains:

*   `generated_at`: An ISO 8601 timestamp (UTC) of when the file was created.
*   `git_sha`: The Git commit hash of the code used for the run.
*   `python_version`, `platform`: Details about the execution environment.
*   `command`: The exact command-line invocation used to run the pipeline.
*   `config`: The effective configuration values, with secrets masked.
*   `inputs`: Descriptions of the source files and key parameters.
*   `stats`: A dictionary of statistics, including `rows_total`, `rows_kept`, `rows_dropped`, and the `output_sha256` checksum of the CSV file.
*   `schema`: The name of the validation schema applied to the data.

### 3. Validation and Quality Reports

*   **Failure Cases**: If any rows in the dataset fail validation against the Pandera schema (e.g., wrong data type, value out of range), they are saved to a `_failure_cases.csv` file for inspection.
*   **Table Quality**: The `table-quality` utility (and most pipelines) generates a `_quality_report_table.csv` with detailed statistics for each column (e.g., null counts, uniqueness, mean, std) and a `_data_correlation_report_table.csv` for numeric columns.

## Pipeline-Specific Artifacts and Columns

### Pipeline Metadata Columns

All exported tables include two standard metadata columns:

*   `pipeline_version`: The version of the `chembl-data-acquisition` package.
*   `timestamp_utc`: The UTC timestamp marking the start of the pipeline run.

### Document Pipeline

*   **Classification Columns**: This pipeline adds several columns to classify publications, including `publication_class` (`review`, `experimental`, or `unknown`) and the scores used to derive it.
*   **Quality Report (`.quality.json`)**: In addition to the standard files, this pipeline generates a JSON report summarizing DOI coverage and any errors encountered while fetching data from upstream services.

### Activity Pipeline

*   **Derived Bounds**: The pipeline calculates `lower_value` and `upper_value` columns from the standard ChEMBL activity columns (`standard_value`, `standard_relation`, etc.) to provide a canonical range for activity values. This is controlled by the `activity_bounds` configuration.
*   **Enrichment Columns**: Based on the `activity_enrichment` configuration, the pipeline can add an `action_type` column (e.g., `inhibition`, `activation`) and a `properties_hash` column.

### Target Pipeline

*   **Staged Exports**: This is the only pipeline that currently supports a separate raw data dump via the `--raw-out` argument. This allows you to inspect the data before the final normalization and validation steps.

### Test Item Pipeline

*   **Enriched Data**: The output includes columns enriched with data from PubChem (e.g., `pubchem_cid`, `pubchem_iupac_name`) and parent molecule information derived from the molecule catalog (`parent_molecule_chembl_id`).
