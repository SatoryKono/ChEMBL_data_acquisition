# Output Reference

This document describes the files generated by the ChEMBL data acquisition pipelines.

## Directory Structure

By default, all output files are written to the directory specified by `local.io.output_dir` in your configuration (typically `~/.local/share/chembl-da/output`).

A typical run for a single pipeline (e.g., `get-activity-data`) will produce a set of related files, all sharing a common base name:

```
output/
├── output.activities_20240101.csv
├── output.activities_20240101.meta.yaml
├── output.activities_20240101_failure_cases.csv
└── output.activities_20240101_quality_report_table.csv
```

---

## Primary Data Files

### Deterministic CSVs (`*.csv`)

The main output of each pipeline is a CSV file containing the processed data. These files are generated deterministically, meaning that given the same input and configuration, the output file will be identical byte-for-byte. This is achieved by:

*   Sorting columns alphabetically.
*   Sorting rows based on a predefined key.
*   Using consistent encoding (`utf-8-sig`) and formatting.

---

## Metadata and Quality Reports

For each primary data file, several sidecar files are generated to provide metadata, validation results, and quality metrics.

### Metadata Sidecar (`*.meta.yaml`)

This is the most important sidecar file. It captures all the necessary information to reproduce the output, including:

*   **`generated_at`**: An ISO 8601 timestamp of when the file was created.
*   **`git_sha`**: The Git commit hash of the code used to generate the file.
*   **`command`**: The exact command-line invocation that was run.
*   **`config`**: The effective configuration used for the run (with secrets masked).
*   **`stats`**: Key statistics, including the number of rows processed and the SHA-256 checksum of the output CSV.

### Validation Failures (`*_failure_cases.csv`)

If any rows from the input data fail validation against the target schema (defined using Pandera), they are saved to this file for inspection. This ensures that the primary output file contains only valid data.

### Table Quality Reports (`*_quality_report_table.csv`)

This file contains a report generated by `library.table_quality`, providing column-level statistics for the output data, such as:

*   Missing value counts.
*   Uniqueness.
*   Data type distribution.

### Document Quality Report (`*.quality.json`)

Specifically for the document pipeline, this JSON file provides metrics on DOI coverage and errors encountered when fetching data from external publication services.

## Key Columns Added by Pipelines

During processing, several standard columns are added to the data to aid in tracking and analysis:

*   **`pipeline_version`**: The version of the `chembl-data-acquisition` package used.
*   **`timestamp_utc`**: The UTC timestamp of when the pipeline run was initiated.
*   **`lower_value` / `upper_value`**: In the activity pipeline, these columns contain calculated numeric bounds for activity values.
*   **`publication_class`**: In the document pipeline, this column contains the final classification of the publication (e.g., `review`, `experimental`).
