# Процесс обеспечения качества (живой документ)

Этот документ служит каноническим чек-листом для валидации стека загрузки данных ChEMBL. Поддерживайте его в актуальном состоянии при добавлении новых сервисов, конвейеров и политик, чтобы остальные руководства могли ссылаться сюда без дублирования инструкций.

## 1. Среда

1. Установите зафиксированные зависимости:
   ```bash
   pip install -r requirements-lock.txt
   ```
2. При необходимости добавьте редактируемый пакет для локальных точек входа:
   ```bash
   pip install -e .
   ```
3. Экспортируйте `PYTHONPATH=.` — так вспомогательные скрипты и детерминированные писатели однозначно находят пакеты.
4. Убедитесь, что опциональные зависимости (`responses`, `hypothesis`, `psutil`, `pytest-benchmark`) доступны, если вы планируете запускать соответствующие тестовые наборы; иначе они будут пропущены.

## 2. Статический анализ и форматирование

Запускайте команды из корня репозитория. Они должны завершаться без диагностик.

```bash
ruff check .
ruff format --check .
mypy --strict
```

## 3. Запуск тестов

1. Быстрая проверка на регрессии:
   ```bash
   pytest --maxfail=1 --durations=10
   ```
2. Полный набор с отображением предупреждений для последующего анализа.
   Используйте тихий режим (`-q`) для регулярных сертификационных прогонов.
   Переключайтесь на подробный вывод (`-vv`), когда нужна детализированная диагностика:
   ```bash
   pytest -q --disable-warnings
   ```

## 4. Проверка детерминизма и CLI

1. Убедитесь, что CSV формируются детерминированно:
   ```bash
   PYTHONPATH=. python -m library.utils.cli_tools.check_determinism --log-level DEBUG
   ```
2. Прогоним минимум один CLI конвейер в режиме сухого запуска, чтобы гарантировать корректность аргументов. Например:
   ```bash
   PYTHONHASHSEED=0 PYTHONPATH=. python scripts/get_activity_data.py --input tests/data/activity_ids_small.csv \
       --output /tmp/activities.csv --limit 10 --dry-run --log-level INFO
   ```
   При необходимости заменяйте скрипт на другие конвейеры, чтобы покрыть свежие изменения.

## 5. Отчётность

Фиксируйте вывод команд (статус, количество ошибок, временные метки) в журнале аудита — как правило, `docs/code_review.md` — при каждом обновлении сертификации репозитория. Делитесь сводками через ссылки на этот живой документ вместо копирования чек-листа.

## 6. QA постобработки документов

Экспорт документов теперь включает автоматическую регрессионную проверку относительно легаси-книги Power Query.

1. Заполните `data/input/full/document.csv` эталонным выгрузочным файлом.
2. Запустите конвейер документов (`python -m scripts.get_document_data ...`) и убедитесь, что он формирует:
   * `output.document_YYYYMMDD.csv`
   * `qa_document_postprocessing_report_YYYYMMDD.json`
   * `qa_document_postprocessing_report_YYYYMMDD.md`
   * `qa_document_postprocessing_diff_YYYYMMDD.csv` (появляется только при расхождениях)
3. Либо выполните QA-скрипт напрямую:
   ```bash
   python -m qa.check_document_postprocessing \
       --base-path data \

       --ref input\\full\\document.csv \
       --actual output\\document\\preprocessed_output.document_YYYYMMDD.csv

       --out output\\document\\output.document_YYYYMMDD.csv

   ```
4. Рассматривайте ненулевой код выхода как блокирующую ошибку; для устранения опирайтесь на Markdown-сводку и извлечённые различия.
