# План запуска задач по устранению зависания `scripts/get_testitem_data.py`

## Обзор

Цель: устранить зависание пайплайна на стадии `attach_parent_molecule_ids` при запуске `scripts/get_testitem_data.py` с ограничением `--limit 10`.

Ниже приводится последовательность задач, подготовленная к непосредственному выполнению. Для каждой указаны цели, входные данные, необходимые инструменты и ожидаемые артефакты.

---

## Задача 1. Репродукция зависания и фиксация базового состояния

- **Цель:** подтвердить зависание и собрать исходные метрики.
- **Команда запуска:**
  ```bash
  python scripts/get_testitem_data.py --config config.yaml --input data/input/testitem.csv --limit 10
  ```
- **Действия:**
  1. Очистить кэши `cache/` и `~/.cache/chembl-da` (при необходимости).
  2. Запустить команду, дождаться появления `parent_lookup_fallback_summary` и отсутствия дальнейших логов в течение ≥10 минут.
  3. Включить `faulthandler.dump_traceback_later(60)` и собрать дампы стеков по `SIGINT`.
  4. Сохранить полный лог и стек-трейсы в `logs/baseline/`.
- **Артефакты:**
  - `logs/baseline/pipeline.log`
  - `logs/baseline/thread_dump.txt`

---

## Задача 2. Расширение диагностического логирования

- **Цель:** добавить подробные логи на стадии parent lookup и сетевых вызовов.
- **Входные файлы:**
  - `scripts/get_testitem_data.py`
  - `library/testitem_pipeline/catalog/__init__.py`
- **Действия:**
  1. Добавить DEBUG/INFO сообщения для старта/завершения стадий, размеров батчей, состояния кэша.
  2. Включить логирование HTTP-клиента (тайминги, ретраи).
  3. Протоколировать состояние очередей/исполнителей перед ожиданиями.
- **Проверка:** повторный запуск команды из Задачи 1, подтверждение наличия новых логов.
- **Артефакты:** обновлённые файлы и лог `logs/diagnostics/pipeline_debug.log`.

---

## Задача 3. Анализ условий запуска полной синхронизации каталога

- **Цель:** подтвердить, что полная синхронизация каталога родителей вызывается при `uncovered_children > 0` и отсутствии кэша.
- **Действия:**
  1. Проанализировать вычисление `needs_full_sync` в `attach_parent_molecule_ids`.
  2. Зафиксировать влияние фильтров `MoleculeCatalogCfg` (особенно `parent_molecule_chembl_id__isnull=false`).
  3. Подготовить вывод с указанием точных строк и условий.
- **Артефакты:** аналитическая записка `docs/findings/full_sync_condition.md`.

---

## Задача 4. Подтверждение эффекта фильтров конфигурации

- **Цель:** доказать, что текущий фильтр исключает parentless-молекулы и делает full sync бессмысленной.
- **Действия:**
  1. Выполнить выборку из API с фильтром `parent_molecule_chembl_id__isnull=false`.
  2. Сравнить с набором идентификаторов без родителей.
  3. Описать выводы и ссылку на конфиг.
- **Артефакты:** отчет `docs/findings/catalog_filter_effect.md`.
