# Анализ расхождений PubChem-обогащения между `get_testitem_data.py` и `get_data.py`

## Ключевые отличия конфигурации и рантайма

| Компонент | Поведение при запуске `get_testitem_data.py` | Поведение при запуске `get_data.py` | Влияние |
|-----------|---------------------------------------------|--------------------------------------|---------|
| Парсер CLI | Собственный CLI добавляет флаг `--pubchem-enable` и прокидывает его в `TestitemPipelineOptions.pubchem_enabled`.【F:library/cli/commands/get_testitem_data.py†L525-L565】【F:library/cli/commands/get_testitem_data.py†L900-L935】 | Оркестратор строит единый список аргументов и не добавляет `--pubchem-enable` для этапа testitem; все шаги получают только общие параметры (`--base-path`, `--input-dir`, `--output-dir`, `--config`, `--limit`, `--log-level`).【F:scripts/get_data.py†L165-L184】 | Без явного флага этап testitem полагается на значение `cfg.pubchem.enable`. Если глобальный конфиг отключает PubChem, обогащение не запускается. |
| Управление конфигом | `run_cli_command` загружает конфигурацию один раз и передает `pubchem_enable` в пайплайн, даже если в YAML PubChem выключен.| Скрипт-оркестратор не проверяет `cfg.pubchem.enable` и не переинициализирует секцию PubChem.| При `cfg.pubchem.enable = false` либо отсутствии секции весь этап завершается без enrichment.|
| Рантайм-поведение пайплайна | При `pubchem_enabled=True` пайплайн выполняет `augment_pubchem` и при необходимости запускает fallback-обогащение на финализации, чтобы заполнить пустые колонки.【F:library/pipelines/testitem/cli.py†L768-L779】【F:library/pipelines/testitem/cli.py†L1213-L1241】 | При `pubchem_enabled=False` пайплайн выводит предупреждение и пропускает заполнение колонок, оставляя `pubchem_*` пустыми.【F:library/pipelines/testitem/cli.py†L768-L777】 | В интегрированном запуске итоговый CSV содержит только пустые PubChem-колонки. |
| Расширенный оркестратор | Современный CLI (`library/cli/commands/get_data.py`) перед запуском шага принудительно включает PubChem и явно добавляет `--pubchem-enable` в команду подпроцесса.【F:library/cli/commands/get_data.py†L1404-L1466】 | Скрипт `scripts/get_data.py` не содержит аналогичной логики; он устарел и не синхронизирован с новым оркестратором. | Разница в поведении проявляется только в «легковесном» скрипте. |

## Причина пустых PubChem-полей в интегрированном запуске

`scripts/get_data.py` запускает `get_testitem_data.py` без флага `--pubchem-enable`. Если используемый YAML-конфиг для сводного запуска не содержит включённой секции `sources.pubchem` (или в окружении выставлен `CHEMBL_DA_PUBCHEM_ENABLE=false`), то внутри пайплайна `pubchem_enabled` остаётся ложным и обогащение явно пропускается. Пайплайн фиксирует это предупреждением `pubchem_augmentation_disabled`, после чего финализатор записывает CSV с пустыми `pubchem_*` колонками.【F:scripts/get_data.py†L165-L184】【F:library/pipelines/testitem/cli.py†L768-L777】 При одиночном вызове `get_testitem_data.py` CLI активирует флаг `pubchem_enable`, поэтому та же конфигурация приводит к заполненным значениям.

## Рекомендованные исправления

| № | Этап | Файл / функция | Причина отсутствия данных | Предлагаемое исправление |
|---|------|----------------|---------------------------|--------------------------|
| 1 | Передача аргументов | `scripts/get_data.py::build_forward_args` | В общий список аргументов не добавляется `--pubchem-enable`, поэтому пайплайн наследует (возможно отключённый) конфиг. | Вставить целевую проверку `if stage.name == "testitem"` и добавлять `--pubchem-enable` перед вызовом подпроцесса. |
| 2 | Страховка конфигурации | `scripts/get_data.py::run_stage` | Оркестратор не синхронизирует секцию PubChem перед запуском шага. | Перед формированием команды загружать конфигурацию (или читать переменную окружения) и, при необходимости, принудительно создавать `sources.pubchem.enable = true`, аналогично `_ensure_pubchem_enabled` в `library/cli/commands/get_data.py`.【F:library/cli/commands/get_data.py†L1404-L1464】 |
| 3 | Документация/DevOps | README / конфигурационные инструкции | В отсутствие флага пользователи не знают, что интегрированный запуск требует явного включения PubChem. | Обновить руководства, добавив требование передавать `--pubchem-enable` или использовать обновлённый оркестратор `library/cli/commands/get_data.py`. |

Реализация пунктов 1–2 синхронизирует поведение «тонкого» скрипта с новым оркестратором и устраняет расхождение: даже минимальная конфигурация без секции PubChem приведёт к включённому обогащению, а при необходимости можно явно отключить его флагом `--no-pubchem-enable`.
