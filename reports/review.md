## Ключевые проблемы и рекомендации

### Structure
1. Скрипты завязаны на `_bootstrap` и ручные манипуляции `sys.path`, что ломает mypy и усложняет переиспользование. Рекомендуется выделить тонкий CLI слой, импортирующий готовые entrypoints из `library.cli.entrypoints.*` без динамики.
2. `library/cli_utils.py` реализует универсальный раннер, но содержит логику формирования схемы/валидаторов. Стоит декомпозировать на модуль с чистыми протоколами + исполнение, чтобы стабилизировать контракт для сторонних пайплайнов.

### Config
1. Нет явной версионности для `config/config.yaml` и связанных словарей — `.meta.yaml` генерируется, но не валидируется. Нужно прописать в `library/io/metadata.py` проверку `pipeline_version` и отказ при несовпадении.
2. ENV-алиасы описаны в коде, но нет автогенерации документации. Рекомендуется добавить проверку `tools/profile_activity_pipeline.py` или отдельный скрипт, который выгружает таблицу алиасов в README.

### Quality
1. Критический NameError из-за отсутствия `import numbers` и `import math` в `library/cli/entrypoints/activity.py`. Это ломает e2e и реальные запуски. Добавить импорт и покрыть smoke-тестом на completion-логику.
2. mypy фиксирует ~600 ошибок, большая часть — отсутствующие типы pandas/yaml/requests. Нужно включить dev-зависимости и добавить `py.typed`-пакеты (`types-PyYAML`, `pandas-stubs`) в обязательные deps либо частично типизировать вручную.
3. `library/cli_utils.py` хранит динамические словари `required_cols` без аннотаций. Стоит вынести их в dataclass и дать явные типы.

### Errors & Stability
1. Retry-логика `_emit_completion_message` падает до того, как очищает ресурсы. Добавить unit-тест с имитацией `streamed_metrics` и убедиться, что NameError не повторяется.
2. В `library/cli_utils.run_pipeline` исключение `PipelineError` приводится к коду возврата без логирования, что затрудняет анализ падений при отказах внешних сервисов; стоит фиксировать ошибку и контекст перед возвратом.
3. В `library/cli_utils.run_pipeline` отсутствует fail-fast для случаев отсутствия `schema`. Стоит логировать предупреждение и запрещать запись, если schema обязательна.

### Performance
1. Обогащение `activity_extended_document_join` выполняется в pandas без ограничений — на проде нужны батчи или join по индексам. Рассмотреть переход на `merge` с категориальными столбцами.
2. Rate-limiter подключается только для Chembl, но не для OpenAlex/Crossref клиетов — стоит унифицировать через `configure_rate_limiters`.

### Testing
1. Структурированные отчёты (`reports/test_report.json`, `reports/test_summary.md`) формируются только при запуске `scripts/run_tests.py`, тогда как `pytest -q` остаётся основной командой в README/Makefile. Нужна интеграция скрипта в CI и документацию по его запуску.
2. Тесты не ловят NameError из `_emit_completion_message`; нужен unit-тест на `activity.main` после пайплайна с включёнными метриками.
3. Для CLI не хватает property-based тестов на схемы Pandera — можно подключить Hypothesis (уже в dev deps).

### План PR-ов
1. **Hotfix (PR#1):** починить импорт `numbers`/`math`, добавить unit-тесты на `_emit_completion_message`, обновить requirements-dev для типов. Категории: Errors, Testing.
2. **Инфраструктура (PR#2):** настроить `pre-commit`/CI с обязательным запуском `pytest --json-report`, `ruff`, `mypy`. Добавить генерацию отчётов в `scripts/run_tests.py`. Категории: Testing, Quality.
3. **Среднесрочный (PR#3):** декомпозировать `library/cli_utils`, типизировать ключевые протоколы, добавить структуру для schema/validators. Категории: Structure, Quality.
4. **Долгосрочный (PR#4):** оптимизация postprocessing (батч-джоины, профилирование), унификация rate-limiter-ов и документирование конфигов. Категории: Perf, Config.
