# Отчёт по диагностике отсутствующего лога для `get_activity_data`

| Потенциальная причина | Подтверждена | Комментарий | Исправление |
|-----------------------|--------------|-------------|-------------|
| Скрипт использует устаревший каталог `logs/` и не учитывает перенос в `data/logs/` | Да | В `scripts/get_activity_data.py` путь к лог-файлу формировался вручную через `Path("logs")`, поэтому файл создавался вне нового каталога и терялся в окружениях CI. | Логирование переведено на `setup_cli_logging`, а путь берётся из общего helper'а с автоматическим созданием `data/logs`. |
| Отсутствие меток о запуске и завершении пайплайна в общем логе | Да | До исправления файл содержал только сообщения побочных компонентов, что затрудняло проверку успешного завершения. | Добавлены явные события `Starting pipeline` и `Export complete` в `main()`. |
| Неконсистентная дата в имени файла (только YYYYMMDD) | Да | Старый формат порождал коллизии при нескольких запусках за сутки. | Новый суффикс `YYYYMMDD_HHMM` реализован в `setup_cli_logging` и используется CLI. |
| Невозможность воспроизвести проблему автоматически | Да | Не хватало end-to-end теста, контролирующего создание лог-файла. | Добавлен smoke-тест `tests/test_activity_logging.py`, который проверяет наличие файла и ключевых сообщений. |
